# 1. 서론

차량 애드혹 네트워크(Vehicular Ad Hoc Network, VANET)는 주행 중인 차량이 주변 차량 또는 도로변 장치와 직접 무선통신을 수행하는 네트워크 환경이다. 이 환경에서는 차량 위치, 속도, 차로 밀도, 연결 가능한 이웃 차량 집합이 시점마다 계속 변한다. 따라서 같은 라우팅 프로토콜을 사용하더라도 현재 무선 채널의 혼잡 정도와 현재 형성된 차량 간 연결 구조가 달라지면, 동일한 제어 패킷을 같은 방식으로 처리하더라도 최종 경로 형성 결과는 달라질 수 있다. 본 연구는 이러한 문제를 IEEE 802.11bd 기반 차량 통신 환경에서 다룬다. IEEE 802.11bd는 고속 이동 환경에서도 차량 간 직접 통신을 지원하도록 설계된 최신 차량 통신 표준이지만, 실제 운용 환경에서는 여전히 시점별 채널 점유 수준과 동적 토폴로지 변화가 라우팅 성능을 크게 좌우한다. 따라서 IEEE 802.11bd 기반 환경에서도 현재 시점의 네트워크 상태를 반영하여 개별 제어 패킷의 전달 여부를 조정하는 상태 적응형 기준이 필요하다.

본 연구는 이러한 상태 적응형 판단 필요성을 애드혹 온디맨드 거리 벡터(Ad hoc On-Demand Distance Vector, AODV) 라우팅의 경로응답(Route Reply, RREP) 전달 과정에서 구체화한다. AODV는 먼저 경로요청(Route Request, RREQ) 패킷으로 요청 노드에서 목적지 노드까지 도달 가능한 경로를 탐색하고, 이후 경로응답(Route Reply, RREP) 패킷으로 탐색된 경로 정보를 목적지 노드에서 원래 요청 노드 방향으로 역방향 전달하여 최종 경로를 형성한다. 이 과정에서 현재 RREP를 처리 중인 차량이 해당 RREP를 다음 차량으로 계속 전달할지, 아니면 중단할지를 판단하는 절차는 최종 라우팅 경로 복원 여부를 직접 좌우한다. RREP 전달이 지연되거나 중단되면 이미 탐색된 경로 정보가 요청 노드까지 도달하지 못할 수 있고, 그 결과 경로탐색 성공 횟수, 경로탐색 실패 횟수, 평균 경로탐색 지연, 경로오류 발생 횟수와 같은 후속 성능 결과가 함께 달라질 수 있다.

본 연구는 현재 RREP를 처리 중인 차량이 측정한 Channel Busy Percentage 값만으로는 이러한 차이를 충분히 설명하기 어렵다고 본다. 동일한 Channel Busy Percentage 값이 관측되더라도 현재 차량 주변의 이웃 차량 수가 다르면 실제 전송 경쟁 정도가 달라질 수 있고, 현재 RREP 패킷에 기록된 hop count 값이 다르면 해당 RREP가 목적지 인접 전달 구간에 있는지 또는 아직 여러 중간 차량을 더 거쳐야 하는 구간에 있는지가 달라질 수 있기 때문이다. 따라서 본 연구는 현재 RREP를 처리 중인 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부를 함께 사용하여 현재 시점에 적용할 두 개의 임계값, 즉 CBP low threshold 값과 CBP high threshold 값을 계산한다.

본 연구의 핵심은 RREP 전달 여부를 직접 이진 분류하는 것이 아니라, AODV의 RREP 포워딩 결정에 실제로 사용될 두 개의 threshold 값을 현재 상태에 따라 동적으로 추정하는 데 있다. 이를 위해 본 연구는 먼저 오프라인 로그 분석 단계에서 동일하거나 유사한 입력 상태에서 어떤 threshold 조합이 좋은 성능을 보였는지를 정리하고, 그 결과를 회귀모델의 학습 목표값으로 사용한다. 이후 온라인 RREP 처리 단계에서는 현재 차량이 관측한 입력 변수 값 조합을 회귀모델에 넣어 해당 시점에 사용할 두 threshold 값을 즉시 계산한다. 이와 같이 본 연구는 오프라인 상태별 성능 분석과 온라인 threshold 추정을 연결하여, 상태 적응형 RREP 포워딩 결정 절차를 IEEE 802.11bd 기반 VANET 환경에 적용한다.

본 논문의 구성은 다음과 같다. 2장에서는 관련 연구를 문제 대상, 입력 정보, 제어 대상, 출력 형태의 관점에서 정리하고 본 연구의 위치를 명확히 한다. 3장에서는 IEEE 802.11bd 기반 차량 통신 환경, AODV의 RREQ/RREP 절차, Channel Busy Percentage의 해석, 그리고 두 threshold 기반 RREP 전달 규칙을 이해하기 위한 Preliminary를 설명한다. 4장에서는 학습 데이터 구성, 입력 변수 정의, 점수 계산, 상태별 학습 목표 threshold 선택, 회귀모델 학습, 그리고 실제 RREP 포워딩 결정 적용 절차를 순서대로 설명한다.

# 2. Related Work

차량 네트워크와 차량 대 모든 것 통신(Vehicle-to-Everything, V2X) 환경에서는 이동성에 따른 연결 구조 변화, 무선 채널 점유 상태 변화, 보안 처리 비용, 메시지 관리 구조, 그리고 평가 환경의 현실성 부족이 반복적으로 연구되어 왔다 [ref]. JKSCI에서 확인한 유사 주제 논문들은 크게 네 부류로 정리할 수 있다. 첫째는 AODV 기반 라우팅 절차를 차량 환경에 맞게 확장하는 연구이다 [ref]. 둘째는 실제 도시 구조를 반영하여 VANET 평가 환경의 현실성을 높이는 연구이다 [ref]. 셋째는 인증서 취소목록(Certificate Revocation List, CRL) 배포 및 처리 지연을 줄이기 위한 차량 통신 보안 운용 연구이다 [ref]. 넷째는 차량 메시지 저장, 조회, 플랫폼 구성과 같은 V2X 서비스 프레임워크 연구이다 [ref].

첫 번째 부류인 AODV 확장 연구는 라우팅 절차 자체를 조정하여 성능을 개선하는 데 초점을 둔다. 예를 들어, 소프트웨어 정의 네트워킹(Software-Defined Networking, SDN) 기반 VANET에 SDN 비지원 차량을 통합하기 위해 AODV 절차를 확장한 연구는 다중 홉 통신 절차와 서비스 범위를 넓히는 방향을 제시하였다 [ref]. 또 다른 MANET 계열 연구는 노드별 사용 가능 통신 자원을 고려하여 AODV 기반 라우팅의 평균 수신율을 개선하는 방향을 제안하였다 [ref]. 이들 연구는 모두 라우팅 절차의 수정이 성능에 중요함을 보여주지만, 제어 대상은 주로 경로 선택 구조 또는 라우팅 확장 절차 자체이다. 반면 본 연구의 제어 대상은 AODV 내부의 특정 순간, 즉 현재 RREP를 처리 중인 차량의 재포워딩 결정 절차이다. 또한 기존 연구가 주로 경로 선택 또는 네트워크 구조 적응을 다루는 반면, 본 연구는 현재 차량이 관측한 채널 상태와 RREP 전달 단계를 함께 사용하여 두 개의 threshold 값을 계산한다는 점에서 입력 정보와 출력 구조가 다르다.

두 번째 부류인 평가 환경 현실화 연구는 결과 해석의 전제를 제공한다. 실제 도시 환경을 반영한 디지털 트윈 기반 VANET 시뮬레이션 연구는 단순 가상 도로와 실제 도로 구조 기반 환경 사이에서 성능 차이가 크게 나타날 수 있음을 보였고, 차량 밀도와 동적 토폴로지 변화가 평가 결과에 큰 영향을 준다는 점을 강조하였다 [ref]. 이는 본 연구가 단일 Channel Busy Percentage 값만으로 RREP 전달 결과를 설명하기 어렵다고 보는 문제의식과 직접 연결된다. 즉, 같은 채널 점유 수준이 관측되더라도 그 시점의 차량 밀도와 연결 구조가 다르면 실제 전달 결과가 달라질 수 있으며, 이 때문에 현재 상태를 반영한 적응형 전달 기준이 필요하다.

세 번째 부류인 차량 통신 보안 및 자원 처리 연구는 제어 대상은 다르지만 비교 축을 제공한다. 예를 들어, 차량이 직접 수행하던 CRL 관련 계산을 도로변 장치(Road Side Unit, RSU)로 이전하여 차량 측 계산 지연을 줄이는 연구는 지연 민감 환경에서 처리 위치가 성능에 직접 연결됨을 보였다 [ref]. 또 진화형 멀티미디어 브로드캐스트 멀티캐스트 서비스(evolved Multimedia Broadcast Multicast Service, eMBMS) 기반 CRL 배포 연구와 블록체인 기반 지역 CRL 연구는 데이터 전달 방식과 처리 구조 변경이 운용 성능을 개선할 수 있음을 보였다 [ref]. 이들 연구는 라우팅 제어 패킷의 전달 여부를 직접 다루지는 않지만, 차량 통신 환경에서 특정 절차를 어느 시점에 어떤 기준으로 수행하느냐가 최종 성능을 바꾼다는 점에서 본 연구와 문제 구조를 공유한다.

네 번째 부류인 V2X 메시지 및 플랫폼 연구는 상위 서비스 구조를 다룬다. 기본 안전 메시지(Basic Safety Message, BSM) 저장 및 조회 프레임워크 연구는 Event-Sourcing과 명령-조회 책임 분리(Command Query Responsibility Segregation, CQRS) 구조를 이용하여 메시지의 안전한 저장과 실시간 조회를 강조하였다 [ref]. 커넥티드 카 플랫폼 아키텍처 연구와 협대역 사물인터넷(NarrowBand-Internet of Things, NB-IoT) 기반 차량 관제 시스템 연구는 차량 정보 수집, 모니터링, 제어, 서비스 확장 구조를 중심으로 설명하였다 [ref]. 이들 연구는 데이터 관리와 서비스 계층 설계에는 유의미하지만, 라우팅 경로 형성 과정에서 특정 제어 패킷을 전달할지 중단할지를 상태 적응적으로 결정하는 문제를 직접 다루지는 않는다.

정리하면, JKSCI에서 확인한 유사 연구들은 라우팅 절차 확장, 평가 환경 현실화, 보안 처리 최적화, 메시지 및 플랫폼 구조라는 서로 다른 문제를 다룬다. 그러나 현재 RREP를 처리 중인 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 해당 hop count 값이 1 이하인지 여부를 함께 사용하여 CBP low threshold 값과 CBP high threshold 값을 동적으로 추정하고, 그 값을 실제 RREP 포워딩 결정 절차에 직접 적용하는 구조는 이번에 확인한 유사 논문군에서 직접 확인되지 않았다. 따라서 본 연구는 기존 차량 네트워크 적응성 문제를 계승하면서도, 그 적응 기준을 RREP 포워딩 결정 단계의 상태 적응형 threshold 추정 문제로 구체화한다는 점에서 차별성을 가진다.

# 3. Preliminary

## 3.1 IEEE 802.11bd 기반 차량 통신 환경

IEEE 802.11bd는 차량 간 직접 통신과 차량-도로변 장치 간 통신을 지원하는 최신 차량 통신 표준이다. 이 표준은 고속 이동 환경에서도 패킷 전송 성능을 유지하기 위한 물리계층과 매체접근제어계층 기능을 제공한다. 그러나 실제 차량 운용 환경에서는 같은 IEEE 802.11bd 기반 통신 설정을 사용하더라도 특정 시점의 차량 밀도, 도로 구간별 동시 전송 수, 차량 간 연결 구조가 계속 달라진다. 따라서 특정 시점에 관측한 채널 상태와 이후 패킷 전달 결과의 관계도 시점마다 달라질 수 있다. 본 연구가 고정된 하나의 RREP 전달 기준 대신 현재 상태에 따라 달라지는 threshold 값을 추정하려는 이유가 여기에 있다.

## 3.2 AODV의 RREQ/RREP 절차와 RREP 포워딩 결정의 의미

AODV는 경로가 필요할 때만 경로를 탐색하는 온디맨드 라우팅 프로토콜이다. 요청 노드는 RREQ를 송신하여 목적지까지 도달 가능한 경로를 찾고, 목적지 노드 또는 유효한 경로를 보유한 노드는 RREP를 생성하여 그 경로 정보를 역방향으로 전달한다. 이 과정에서 RREP는 여러 중간 차량을 거쳐 원래 요청 노드까지 도달해야 최종 경로 형성이 완료된다. 따라서 현재 RREP를 수신한 차량이 그 RREP를 다시 전달할지 여부를 판단하는 순간은 단순 중계 동작이 아니라, 최종 경로 복원 성공 여부를 바꾸는 핵심 제어 지점이다.

본 연구에서 중요한 점은 제어 대상이 AODV 전체 절차가 아니라 현재 RREP를 수신한 차량의 재포워딩 결정이라는 사실이다. 즉, 본 연구는 RREQ 생성 규칙이나 전체 경로 선택 알고리즘을 새로 설계하는 것이 아니라, 이미 진행 중인 경로 응답 전달 과정에서 현재 차량이 해당 RREP를 계속 전달할지 중단할지를 현재 상태에 맞게 결정하는 기준을 설계한다.

## 3.3 Channel Busy Percentage와 두 threshold 기반 전달 규칙

본 연구는 현재 RREP를 처리 중인 차량이 직접 측정한 채널 상태 지표로 Channel Busy Percentage를 사용한다. 이는 해당 차량이 관측한 무선 채널이 얼마나 오랫동안 점유되었는지를 나타내는 값이며, 현재 시점의 채널 혼잡 정도를 직접 반영한다. 오프라인 데이터 구성에서는 이 값이 RREP 재포워딩 결정 사건 로그에 기록되어 있으며, 이웃 차량 수나 경로탐색 관련 집계값은 별도의 1초 단위 진단 로그와 차량 식별자 및 동일 초 구간 기준으로 결합한다. 따라서 Channel Busy Percentage는 현재 판단 시점의 직접 관측값이고, 이웃 차량 수 및 후속 성능 지표는 동일 차량의 동일 1초 구간에서 대응된 집계값이다.

본 연구가 사용하는 기본 RREP 전달 규칙은 두 개의 threshold 값으로 정의되는 허용 구간 규칙이다. 즉, 현재 시점에 적용되는 low threshold 값과 high threshold 값이 주어졌을 때, 현재 차량이 관측한 Channel Busy Percentage가 그 구간 안에 있으면 RREP를 전달하고, 그 구간을 벗어나면 전달하지 않는다. 이 규칙은 식 (1)과 같이 표현할 수 있다.

$$
F_t=
\begin{cases}
1, & l_t \le c_t \le u_t \\
0, & \text{otherwise}
\end{cases}
\tag{1}
$$

식 (1)에서 $c_t$는 시점 $t$에 현재 RREP를 처리 중인 차량이 관측한 Channel Busy Percentage 값이다. $l_t$와 $u_t$는 시점 $t$의 RREP 포워딩 결정에 적용되는 low threshold 값과 high threshold 값이다. $F_t=1$은 해당 RREP를 다시 전달함을 의미하고, $F_t=0$은 전달하지 않음을 의미한다. 본 연구가 threshold 값을 하나가 아니라 두 개로 두는 이유는, 단순히 채널이 혼잡한 경우만 배제하는 것이 아니라 현재 채널 점유 수준이 RREP 재포워딩에 적절한 범위 안에 있는지를 구간 형태로 결정하기 위해서이다.

## 3.4 현재 상태와 threshold 추정 문제

동일한 Channel Busy Percentage 값이 관측되더라도 현재 차량 주변의 이웃 차량 수가 다르면 경쟁 차량 수가 달라질 수 있고, 현재 RREP 패킷에 기록된 hop count 값이 다르면 해당 RREP가 목적지 인접 구간에 있는지 또는 다중 홉 전달 구간에 있는지가 달라질 수 있다. 따라서 적절한 $l_t$와 $u_t$도 현재 상태에 따라 달라져야 한다. 본 연구는 이러한 상태 의존성을 반영하기 위해 현재 RREP를 처리 중인 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부를 입력으로 사용하여 두 개의 threshold 값을 출력하는 회귀모델을 학습한다.

# 4. 제안기법

본 장에서는 오프라인 로그로부터 상태별 학습 목표 threshold 값을 생성하고, 이를 이용해 온라인 RREP 처리 시점의 threshold 값을 추정하는 절차를 설명한다. 전체 과정은 데이터 구성, 점수 계산, 상태별 목표값 선택, 회귀모델 학습, 그리고 온라인 적용의 다섯 단계로 이해할 수 있다.

## 4.1 학습 데이터 구성과 입력 변수 정의

본 연구의 학습 샘플 기본 단위는 현재 RREP를 수신한 차량이 해당 RREP를 다시 전달할지 결정한 1회의 기록이다. 하나의 샘플은 특정 차량, 특정 시각, 특정 RREP 재포워딩 결정에 대응한다. RREP 재포워딩 결정 사건 로그에는 해당 시점의 Channel Busy Percentage 값, hop count 값, 실제 적용된 low threshold 값, 실제 적용된 high threshold 값이 기록되어 있다. 여기에 별도의 1초 단위 진단 로그에서 집계된 이웃 차량 수와 경로탐색 관련 결과를 결합하여 하나의 학습 샘플을 구성한다.

오프라인 데이터 결합에서는 두 로그의 시간을 동일한 1초 기준으로 맞춘다. 먼저 RREP 재포워딩 결정 시각은 내림하여 정수 초 단위로 변환한다. 예를 들어 결정 시각이 12.8초이면 12초 구간으로 처리한다. 이후 동일 차량의 동일 초 구간에 해당하는 진단 로그를 대응시켜 이웃 차량 수, 경로탐색 성공 횟수, 경로탐색 실패 횟수, 평균 경로탐색 지연, 경로오류(Route Error, RERR) 발생 횟수, 경로 무효화 횟수, 경로 삭제 횟수를 해당 샘플에 부여한다. 따라서 본 연구에서 "각 RREP 포워딩 결정 이후에 관측된 결과"라고 할 때는, 개별 결정 사건이 속한 동일 차량의 동일 1초 구간에서 집계된 후행 성능 결과를 의미한다.

전체 실험은 학습용 10개, 검증용 2개, 평가용 2개 실험으로 분리하여 사용한다. 또한 각 실험에서 사용하는 RREP 재포워딩 결정 샘플 수는 최대 60,000개로 제한한다. 이와 같이 실험 단위 분할을 유지하는 이유는 학습과 평가가 동일 실험 결과에 과도하게 의존하지 않도록 하기 위해서이다.

전처리 과정에서는 필수 값이 없는 샘플을 제거한다. 필수 값은 시각, 차량 식별자, hop count 값, Channel Busy Percentage 값, 실제 적용된 low threshold 값, 실제 적용된 high threshold 값이다. 또한 hop count 값은 1 이상 6 이하인 샘플만 사용하고, 실제 적용된 low threshold 값과 high threshold 값은 반올림하여 정수값으로 변환한다. low threshold 값이 high threshold 값보다 큰 샘플은 제어 규칙이 성립하지 않으므로 제외한다.

본 연구는 시점 $t$에서 현재 RREP를 처리 중인 차량의 입력 변수를 $x_t=(c_t,n_t,h_t,d_t)$로 정의한다. 여기서 $c_t$는 현재 차량이 관측한 Channel Busy Percentage 값, $n_t$는 현재 차량이 인식한 이웃 차량 수, $h_t$는 현재 RREP 패킷에 기록된 hop count 값, $d_t$는 hop count 값이 1 이하인지 여부를 나타내는 이진 변수이다. 이진 변수 $d_t$는 식 (2)와 같이 정의한다.

$$
d_t=
\begin{cases}
1, & h_t \le 1 \\
0, & h_t > 1
\end{cases}
\tag{2}
$$

식 (2)에서 $d_t=1$은 현재 RREP가 목적지 인접 전달 구간에 있음을 나타내고, $d_t=0$은 아직 둘 이상의 홉을 더 거쳐야 하는 다중 홉 전달 구간에 있음을 나타낸다. 즉, $d_t$는 위치 정보나 차량 이동 방향을 나타내는 변수가 아니라, 현재 RREP 패킷의 전달 단계가 목적지 인접 구간인지 여부만을 구분하는 변수이다.

$c_t$를 사용하는 이유는 현재 채널 점유 수준을 직접 반영하기 때문이다. $n_t$를 사용하는 이유는 잠재적인 동시 전송 경쟁자의 규모를 반영하기 때문이다. $h_t$를 사용하는 이유는 현재 RREP가 경로상 어느 정도 진행된 상태인지 나타내기 때문이다. $d_t$를 따로 분리하는 이유는 hop count 값 자체와 별도로 목적지 인접 구간과 다중 홉 구간을 이진적으로 구분하는 정보가 포워딩 결정 특성에 별도 영향을 줄 수 있기 때문이다.

## 4.2 RREP 포워딩 결정 결과 점수 정의

본 연구는 하나의 RREP 포워딩 결정이 단일 성능 지표만 바꾸는 것이 아니라, 경로 연결 성공 여부, 실패 횟수, 지연, 오류, 무효화, 삭제를 함께 바꿀 수 있다고 본다. 따라서 특정 threshold 조합의 품질을 평가하기 위해 여러 결과 지표를 결합한 시점 $t$의 점수 $S_t$를 정의한다.

$$
S_t
=
\alpha_1 R^{\mathrm{succ}}_t
-\alpha_2 R^{\mathrm{fail}}_t
-\alpha_3 D_t
-\alpha_4 E^{\mathrm{rerr}}_t
-\alpha_5 E^{\mathrm{inv}}_t
-\alpha_6 E^{\mathrm{del}}_t
\tag{3}
$$

식 (3)에서 $R^{\mathrm{succ}}_t$는 동일 차량의 동일 1초 구간에서 집계된 경로탐색 성공 횟수이고, $R^{\mathrm{fail}}_t$는 경로탐색 실패 횟수이며, $D_t$는 평균 경로탐색 지연이다. $E^{\mathrm{rerr}}_t$는 RERR 발생 횟수, $E^{\mathrm{inv}}_t$는 경로 무효화 횟수, $E^{\mathrm{del}}_t$는 경로 삭제 횟수이다.

본 연구는 가중치를 식 (4)와 같이 설정한다.

$$
\alpha_1=2.0,\quad
\alpha_2=3.0,\quad
\alpha_3=0.02,\quad
\alpha_4=1.0,\quad
\alpha_5=0.25,\quad
\alpha_6=0.1
\tag{4}
$$

식 (4)를 식 (3)에 대입하면 최종 점수식은 식 (5)와 같다.

$$
S_t
=
2.0R^{\mathrm{succ}}_t
-3.0R^{\mathrm{fail}}_t
-0.02D_t
-E^{\mathrm{rerr}}_t
-0.25E^{\mathrm{inv}}_t
-0.1E^{\mathrm{del}}_t
\tag{5}
$$

이 가중치 설정은 각 지표의 역할과 수치 범위를 함께 고려한 설계이다. 경로탐색 성공은 최종 경로 형성의 직접적 긍정 결과이므로 양의 가중치를 준다. 경로탐색 실패는 단순한 성공 부재가 아니라 재탐색 오버헤드와 서비스 단절로 이어질 수 있으므로 성공보다 큰 절댓값의 음의 가중치를 준다. 평균 지연은 밀리초 단위의 연속값으로 다른 횟수 기반 지표보다 수치 범위가 크므로, 다른 항목을 압도하지 않도록 작은 계수를 부여한다. RERR, 경로 무효화, 경로 삭제는 모두 경로 불안정성을 나타내는 음의 결과이므로 음의 가중치를 주되, 경로 단절에 대한 직접성과 빈도 차이를 고려하여 서로 다른 계수를 사용한다. 따라서 식 (5)의 값이 클수록 성공 증가와 실패, 지연, 오류 감소를 함께 반영한 종합 결과가 더 좋다고 해석한다. 다만 현재 확인된 산출물 기준으로는, 식 (5)의 계수가 별도 계수 탐색 결과에서 최종 선택된 조합과 일치한다는 정량 근거는 아직 확인되지 않았다. 계수 탐색 산출물은 후보 조합 비교와 shortlist 회귀평가를 거쳐 $(2.0, 1.0, 2.0, 1.0, 0.25, 0.5)$ 조합을 선택한 것으로 기록하지만, 현재 학습 노트북은 식 (5)의 계수를 직접 사용한다. 따라서 현 단계에서 확인 가능한 사실은 식 (5)가 현재 학습 파이프라인에서 사용된 점수식이라는 점까지이며, 이 값들이 별도 탐색 절차로 최종 확정되었다고 단정할 근거는 부족하다.

## 4.3 상태별 학습 목표 threshold 값 선택

오프라인 로그의 입력 변수는 연속값이므로, 서로 다른 상태에서 관측된 기록을 한꺼번에 비교하면 현재 상태 차이와 threshold 조합 차이가 뒤섞일 수 있다. 따라서 본 연구는 유사한 상태에서 적용된 threshold 조합끼리 비교하기 위해 입력 변수를 이산화하여 상태 범주를 구성한다.

본 연구는 Channel Busy Percentage 값과 이웃 차량 수를 각각 5 단위로 구간화한다. 5 단위 이산화는 상태 수가 지나치게 커져 샘플이 희소해지는 문제와, 반대로 상태 구분이 지나치게 거칠어지는 문제 사이의 균형을 위한 설정이다. hop count 값은 1 이상 6 이하 정수 범위로 사용하고, 앞서 정의한 이진 변수 $d_t$를 함께 사용한다. 이 네 값을 조합하여 상태 범주 $s$를 구성한다.

시점 $t$에서 실제 적용된 low threshold 값과 high threshold 값을 각각 $l_t$, $u_t$로 표기하면, 상태 $s$와 threshold 조합 $(l,u)$에 대한 평균 점수는 식 (6)과 같이 계산한다.

$$
\bar{S}(s,l,u)
=
\frac{1}{N(s,l,u)}
\sum_{t \in \Omega(s,l,u)} S_t
\tag{6}
$$

식 (6)에서 $\Omega(s,l,u)$는 상태 범주 $s$에 속하면서 low threshold 값이 $l$, high threshold 값이 $u$였던 모든 RREP 포워딩 결정 기록 집합이고, $N(s,l,u)$는 그 집합의 기록 개수이다. 여기서 표본 수는 일반적인 전체 데이터 수가 아니라, 같은 상태와 같은 threshold 조합을 가진 기록 수를 의미한다.

본 연구는 기록 수가 너무 적은 조합이 우연한 결과로 선택되는 것을 줄이기 위해 식 (7)의 최소 표본 수 조건을 적용한다.

$$
N(s,l,u) \ge 5
\tag{7}
$$

이후 상태 $s$에서 가능한 threshold 조합들 중 가장 높은 평균 점수를 식 (8)과 같이 정의한다.

$$
\bar{S}_{\max}(s)=\max_{l,u}\bar{S}(s,l,u)
\tag{8}
$$

각 조합이 최고 점수와 얼마나 차이 나는지는 식 (9)로 계산한다.

$$
\Delta(s,l,u)=\bar{S}_{\max}(s)-\bar{S}(s,l,u)
\tag{9}
$$

본 연구는 최고 점수 조합 하나만 기계적으로 선택하지 않고, 최고 점수와 유사한 성능을 보이는 조합들을 먼저 후보군으로 남긴다. 이는 1초 단위 집계 결과에 포함될 수 있는 잡음을 완충하고, 상태별로 지나치게 불안정한 단일 선택을 피하기 위한 것이다. 이를 위해 식 (10)의 조건을 적용한다.

$$
\Delta(s,l,u) \le 0.2
\tag{10}
$$

따라서 상태 $s$의 후보 조합 집합은 식 (11)과 같이 정의한다.

$$
\mathcal{C}(s)=
\left\{(l,u) \mid N(s,l,u)\ge 5,\ \Delta(s,l,u)\le 0.2\right\}
\tag{11}
$$

후보군이 정해지면 본 연구는 사전식 정렬 규칙으로 하나의 대표 threshold 조합을 선택한다. 정렬 우선순위는 다음과 같다. 첫째, low threshold 값이 큰 조합을 우선한다. 둘째, 평균 점수가 큰 조합을 우선한다. 셋째, 기록 개수가 많은 조합을 우선한다. 넷째, high threshold 값과 low threshold 값의 차이가 작은 조합을 우선한다. 다섯째, high threshold 값이 작은 조합을 우선한다.

이 정렬 규칙의 설계 이유는 다음과 같다. low threshold 값을 우선적으로 크게 두는 것은 채널이 지나치게 비어 있는 경우까지 무조건 재전달을 허용하지 않고, 일정 수준 이상의 채널 사용 조건에서만 재전달하도록 하여 불필요한 전달을 억제하기 위한 것이다. 평균 점수와 기록 개수를 뒤따라 고려하는 것은 성능이 좋고 통계적으로 더 안정적인 조합을 선호하기 위해서이다. threshold 폭을 작게 두는 것은 비슷한 성능을 보이는 조합들 사이에서 재전달 허용 구간을 과도하게 넓히지 않기 위한 것이다. high threshold 값을 더 작게 두는 마지막 기준은 비슷한 조건에서 지나치게 높은 채널 점유 수준까지 허용하는 조합보다 상대적으로 보수적인 상한을 선호하기 위한 것이다.

이 과정을 통해 상태 $s$의 대표 low threshold 값과 high threshold 값을 각각 $l_s^\ast$와 $u_s^\ast$로 정의한다. 이 두 값이 이후 회귀모델의 학습 목표값이 된다.

## 4.4 회귀모델 학습 및 평가

오프라인 상태별 대표 threshold 값을 직접 테이블 조회 방식으로만 사용하면, 실제 RREP 처리 시점에 연속적으로 변하는 입력값에 즉시 대응하기 어렵다. 또한 온라인 운용에서는 오프라인 로그에 없던 새로운 입력 조합이 나타날 수 있다. 따라서 본 연구는 상태별 대표 threshold 값을 목표로 하는 회귀모델을 학습하여, 현재 입력값으로부터 두 threshold 값을 직접 추정한다.

회귀모델의 입력은 $x_t=(c_t,n_t,h_t,d_t)$이고, 출력은 시점 $t$에 적용할 low threshold 값과 high threshold 값이다. 모델 출력은 식 (12)와 같이 표현한다.

$$
\hat{y}_t=f_\theta(x_t)=(\hat{l}_t,\hat{u}_t)
\tag{12}
$$

여기서 $\hat{l}_t$와 $\hat{u}_t$는 각각 회귀모델이 예측한 low threshold 값과 high threshold 값이다. 학습 목표값은 식 (13)과 같이 현재 샘플이 속한 상태의 대표 threshold 조합으로 둔다.

$$
y_t=(l_{s_t}^\ast,u_{s_t}^\ast)
\tag{13}
$$

식 (13)에서 $s_t$는 시점 $t$의 입력값이 속한 상태 범주이다. 즉, 동일 상태에 속한 샘플들은 같은 목표 threshold 조합을 공유한다.

학습 전에 입력 4개와 출력 2개를 각각 독립적으로 표준화한다. 이는 서로 다른 값 범위를 갖는 변수들을 동일한 학습 과정에서 안정적으로 다루고, 두 출력값의 스케일 차이가 손실 계산에 편향을 주는 것을 줄이기 위한 것이다.

본 연구는 회귀모델로 다층 퍼셉트론(Multi-Layer Perceptron, MLP)을 사용한다. 모델 구조는 입력층 4개, 첫 번째 은닉층 256개, 두 번째 은닉층 256개, 세 번째 은닉층 128개, 출력층 2개로 구성한다. 은닉층 활성화 함수는 ReLU를 사용하고, 손실함수는 평균제곱오차(Mean Squared Error, MSE)를 사용한다. 손실함수는 식 (14)와 같다.

$$
\mathcal{L}(\theta)
=
\frac{1}{T}
\sum_{t=1}^{T}
\left\|f_\theta(x_t)-y_t\right\|_2^2
\tag{14}
$$

최적화는 학습률 $1\times10^{-3}$의 Adam을 사용한다. 학습은 최대 40 epoch까지 수행하고, 배치 크기는 4096으로 설정한다. 또한 검증 손실 기준 조기 종료를 적용하여 6 epoch 동안 성능이 개선되지 않으면 학습을 중단하고, 3 epoch 동안 개선이 없으면 학습률을 0.5배로 줄이며 최소 학습률은 $1\times10^{-5}$로 둔다. 이러한 설정은 회귀모델이 과적합 없이 안정적으로 수렴하도록 하기 위한 것이다. 각 실험의 RREP 포워딩 결정 결과에서 실제 적용된 하한 임계값과 상한 임계값을 추출하여 학습 목표값으로 사용한다.

평가는 샘플 단위와 상태 단위로 나누어 수행한다. 샘플 단위 평가는 평가 구간의 각 샘플에 대해 예측값과 목표값을 직접 비교하여 low threshold 값과 high threshold 값 각각의 결정계수 $R^2$와 평균절대오차(MAE)를 계산하는 방식이다. 상태 단위 평가는 동일 상태에 속한 평가 샘플들의 예측값을 평균한 뒤 상태별 대표 목표값과 비교하는 방식이다. 샘플 단위 평가는 개별 예측 오차를, 상태 단위 평가는 동일 상태 내 평균적인 수렴 정도를 확인하기 위해 함께 사용한다.

## 4.5 threshold 후처리와 온라인 RREP 적용 규칙

회귀모델이 출력한 $\hat{l}_t$와 $\hat{u}_t$는 연속값이므로 학습 데이터 범위를 벗어나는 값이 나올 수 있고, 두 값의 순서나 간격이 실제 제어 규칙에 맞지 않을 수도 있다. 따라서 본 연구는 회귀모델 출력값에 대해 범위 제한과 최소 간격 조건을 적용한 뒤 최종 threshold 값으로 사용한다.

먼저 low threshold 값과 high threshold 값에 공통으로 허용 범위를 적용한다. 식 (15)와 식 (16)에서 $L_{\min}$과 $L_{\max}$는 실험 설정에서 정한 공통 하한과 상한이며, 본 연구는 각각 0과 100을 사용한다.

$$
\bar{l}_t=
\min\left(L_{\max},\max(L_{\min},\hat{l}_t)\right)
\tag{15}
$$

$$
\bar{u}_t=
\min\left(L_{\max},\max(L_{\min},\hat{u}_t)\right)
\tag{16}
$$

식 (15)와 식 (16)은 회귀모델 출력이 비현실적으로 작은 값이나 큰 값으로 벗어나는 것을 막기 위한 단계이다. 다음으로 두 threshold 값 사이에 최소 간격 조건을 적용한다. $\delta_{\min}$은 두 threshold 값 사이에 유지해야 하는 최소 차이이며, 본 연구는 $\delta_{\min}=5$를 사용한다.

$$
\tilde{l}_t=\bar{l}_t,\qquad
\tilde{u}_t=\max(\bar{u}_t,\tilde{l}_t+\delta_{\min})
\tag{17}
$$

식 (17)의 목적은 high threshold 값이 low threshold 값보다 충분히 크도록 보장하여, 전달 허용 구간이 사라지거나 지나치게 좁아지는 상황을 방지하는 데 있다. 여기서 $\tilde{l}_t$와 $\tilde{u}_t$가 실제 RREP 포워딩 결정에 사용되는 최종 low threshold 값과 최종 high threshold 값이다. 정리하면 본 연구의 온라인 후처리 상수는 $L_{\min}=0$, $L_{\max}=100$, $\delta_{\min}=5$이며, 이는 학습 목표값을 구성한 실험 설정과 동일하다.

최종 온라인 RREP 포워딩 결정은 식 (18)과 같이 수행한다.

$$
Forward_t=
\begin{cases}
1, & \tilde{l}_t \le c_t \le \tilde{u}_t \\
0, & \text{otherwise}
\end{cases}
\tag{18}
$$

즉, 본 연구의 회귀모델은 RREP 전달 여부를 직접 출력하지 않는다. 회귀모델이 출력하는 것은 현재 상태에서 사용할 두 개의 threshold 값이며, 최종 전달 여부는 현재 차량이 측정한 Channel Busy Percentage 값 $c_t$가 그 threshold 구간 안에 있는지 여부로 결정된다. 이 구조는 오프라인 학습 목표값과 온라인 AODV 적용 규칙을 동일한 형태로 연결해 준다.

## 4.6 전체 절차

본 연구의 전체 절차는 다음과 같다.

1. RREP 재포워딩 결정 사건 로그와 1초 단위 진단 로그를 차량 식별자와 동일 초 구간 기준으로 결합하여 학습 샘플을 구성한다.
2. 각 샘플에서 Channel Busy Percentage 값, 이웃 차량 수, hop count 값, hop count 값이 1 이하인지 여부를 입력으로 기록하고, 동일 1초 구간의 성능 집계값을 결과 변수로 연결한다.
3. 식 (5)를 이용하여 각 RREP 포워딩 결정 샘플의 종합 점수 $S_t$를 계산한다.
4. Channel Busy Percentage 값과 이웃 차량 수를 5 단위로 구간화하고, hop count 값과 이진 변수 $d_t$를 함께 사용하여 상태 범주를 구성한다.
5. 같은 상태와 같은 threshold 조합을 가진 샘플들에 대해 평균 점수 $\bar{S}(s,l,u)$를 계산한다.
6. 표본 수가 5 미만인 조합을 제거하고, 최고 평균 점수와의 차이가 0.2 이하인 조합만 후보군으로 유지한다.
7. 후보군에 사전식 정렬 규칙을 적용하여 상태별 대표 low threshold 값 $l_s^\ast$와 대표 high threshold 값 $u_s^\ast$를 선택한다.
8. 상태별 대표 threshold 조합을 목표값으로 하여 MLP 회귀모델을 학습하고, 학습용 10개 실험, 검증용 2개 실험, 평가용 2개 실험 분할에서 성능을 확인한다.
9. 온라인 RREP 처리 시점에는 현재 입력값 $x_t$를 회귀모델에 넣어 $\hat{l}_t$와 $\hat{u}_t$를 계산한다.
10. 회귀모델 출력에 범위 제한과 최소 간격 조건을 적용하여 최종 threshold 값 $\tilde{l}_t$와 $\tilde{u}_t$를 만든다.
11. 현재 차량이 관측한 Channel Busy Percentage 값 $c_t$가 $\tilde{l}_t$ 이상이고 $\tilde{u}_t$ 이하이면 RREP를 전달하고, 그렇지 않으면 전달하지 않는다.

따라서 본 연구는 기본 AODV에 Channel Busy Percentage 기반 RREP 포워딩 결정 절차를 추가하고, 그 절차에서 현재 RREP를 처리 중인 차량이 관측한 채널 점유 수준, 이웃 차량 수, 현재 RREP 패킷의 전달 단계 정보를 함께 사용하여 시점별 low threshold 값과 high threshold 값을 계산한다. 그리고 그렇게 계산된 두 threshold 값을 현재 Channel Busy Percentage 값과 비교함으로써, 현재 상태에 적응하는 RREP 포워딩 결정을 수행한다.
