# 1. 서론

차량 애드혹 네트워크(Vehicular Ad Hoc Network, VANET)는 주행 중인 차량이 주변 차량 또는 도로변 장치와 직접 무선통신을 수행하는 네트워크 환경이다. VANET 환경에서는 차량 위치, 속도, 차로 밀도, 그리고 무선통신이 가능한 이웃 차량 집합이 시점마다 계속 변한다. 따라서 동일한 라우팅 프로토콜을 사용하더라도 현재 무선 채널의 혼잡 정도와 현재 형성된 차량 간 연결 구조가 달라지면, 동일한 제어 패킷을 동일한 규칙으로 처리하더라도 최종 라우팅 경로 형성 성공 여부와 최종 라우팅 경로 형성 완료까지 걸린 시간은 달라질 수 있다. 본 연구는 이러한 문제를 IEEE 802.11bd 기반 차량 통신 환경에서 다룬다. IEEE 802.11bd는 고속 이동 환경에서도 차량 간 직접 통신을 지원하도록 설계된 최신 차량 통신 표준이지만, 실제 운용 환경에서는 시점별 채널 점유 수준과 동적 토폴로지 변화가 여전히 라우팅 성능을 크게 좌우한다. 따라서 IEEE 802.11bd 기반 환경에서도 현재 차량이 관측한 무선 채널 점유 수준, 현재 차량 주변의 이웃 차량 수, 그리고 현재 RREP 패킷에 기록된 hop count를 반영하여 개별 제어 패킷의 처리 규칙을 조정하는 기준이 필요하다.

본 연구는 현재 차량이 관측한 무선 채널 점유 수준과 현재 RREP 전달 단계에 따라 달라지는 처리 기준의 필요성을 애드혹 온디맨드 거리 벡터(Ad hoc On-Demand Distance Vector, AODV) 라우팅의 경로응답(Route Reply, RREP) 전달 단계에 구체적으로 적용한다. AODV는 먼저 경로요청(Route Request, RREQ) 패킷으로 요청 노드에서 목적지 노드까지 도달 가능한 라우팅 경로를 찾고, 이후 경로응답(Route Reply, RREP) 패킷으로 탐색된 라우팅 경로 정보를 목적지 노드에서 원래 RREQ를 보낸 요청 노드 방향으로 역방향 전달하여 최종 라우팅 경로를 형성한다. 따라서 현재 차량이 수신한 RREP를 요청 노드 방향의 다음 차량으로 재전송할지, 아니면 현재 차량에서 중단할지를 결정하는 순간은 단순 중계 동작이 아니라 최종 라우팅 경로 복원 성공 여부를 바꾸는 핵심 제어 지점이다. 현재 차량이 RREP 재전송을 지연하거나 중단하면 이미 탐색된 라우팅 경로 정보가 요청 노드까지 도달하지 못할 수 있고, 그 결과 AODV 라우팅 경로 설정 성공 횟수, AODV 라우팅 경로 설정 실패 횟수, AODV 라우팅 경로 설정 완료까지 걸린 평균 시간, 경로오류 발생 횟수가 함께 달라질 수 있다.

본 연구는 현재 차량이 측정한 Channel Busy Percentage 값만으로는 RREP 재전송 결정 결과의 변화를 충분히 설명하기 어렵다고 본다. 현재 차량이 측정한 Channel Busy Percentage 값이 같더라도 현재 차량 주변의 이웃 차량 수가 다르면 실제 전송 경쟁 정도가 달라질 수 있고, 현재 RREP 패킷에 기록된 hop count 값이 다르면 현재 RREP가 목적지 인접 전달 구간에 있는지 또는 아직 여러 중간 차량을 더 거쳐야 하는 구간에 있는지가 달라질 수 있기 때문이다. 따라서 본 연구는 현재 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부를 함께 사용하여 현재 RREP 재전송 결정에 적용할 Channel Busy Percentage 재전송 허용 구간의 하한값과 상한값을 계산한다.

본 연구의 핵심은 RREP 재전송 여부를 직접 이진 분류하는 것이 아니라, 현재 차량의 RREP 포워딩 결정에 실제로 사용할 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값을 현재 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부의 조합에 따라 동적으로 추정하는 데 있다. 이를 위해 본 연구는 먼저 학습 데이터에서 Channel Busy Percentage 값, 이웃 차량 수, hop count 값, hop count 값이 1 이하인지 여부가 같은 조건에서 어떤 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값 조합이 높은 평균 점수를 보였는지를 정리하고, 그 평균 점수가 가장 높았던 Channel Busy Percentage 재전송 허용 하한값-상한값 조합을 회귀모델의 학습 목표값으로 사용한다. 이후 실제 RREP 처리 시점에는 현재 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부의 조합을 회귀모델에 넣어 그 시점의 RREP 포워딩 결정에 적용할 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값을 즉시 계산한다. 즉, 본 연구는 위 네 입력값 조합별 평균 성능 분석과 실제 RREP 처리 시점의 Channel Busy Percentage 재전송 허용 하한값·상한값 계산을 연결하여, IEEE 802.11bd 기반 VANET 환경에 적용할 RREP 포워딩 규칙을 구성한다.

본 논문의 구성은 다음과 같다. 2장에서는 관련 연구를 문제 대상, 입력 정보, 제어 대상, 출력 형태의 관점에서 정리하고 본 연구의 위치를 명확히 한다. 3장에서는 IEEE 802.11bd 기반 차량 통신 환경, AODV의 RREQ/RREP 전달 구조, Channel Busy Percentage의 의미, 그리고 Channel Busy Percentage 재전송 허용 구간 기반 RREP 포워딩 규칙을 설명한다. 4장에서는 학습 데이터 구성, 입력 변수 정의, 점수 계산, 입력 변수 범주별 학습 목표 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 선택, 회귀모델 학습, 그리고 실제 RREP 포워딩 적용 규칙을 순서대로 설명한다.

# 2. Related Work

차량 네트워크와 차량 대 모든 것 통신(Vehicle-to-Everything, V2X) 환경에서는 이동성에 따른 연결 구조 변화, 무선 채널 점유 상태 변화, 보안 처리 비용, 메시지 관리 구조, 그리고 평가 환경의 현실성 부족이 반복적으로 연구되어 왔다 [ref]. JKSCI에서 확인한 유사 주제 논문들은 크게 네 부류로 정리할 수 있다. 첫째는 AODV 기반 라우팅 규칙을 차량 환경에 맞게 확장하는 연구이다 [ref]. 둘째는 실제 도시 구조를 반영하여 VANET 평가 환경의 현실성을 높이는 연구이다 [ref]. 셋째는 인증서 취소목록(Certificate Revocation List, CRL) 배포 및 처리 지연을 줄이기 위한 차량 통신 보안 운용 연구이다 [ref]. 넷째는 차량 메시지 저장, 조회, 플랫폼 구성과 같은 V2X 서비스 프레임워크 연구이다 [ref]. 현재 [ref] 표시는 최종 원문 대조가 끝난 뒤 실제 서지정보로 교체할 자리표시자이며, 본 절의 문헌 분류 구조는 그 최종 인용 정리를 위한 초안 구조에 해당한다.

첫 번째 부류인 AODV 확장 연구는 라우팅 규칙 자체를 조정하여 성능을 개선하는 데 초점을 둔다. 예를 들어, 소프트웨어 정의 네트워킹(Software-Defined Networking, SDN) 기반 VANET에 SDN 비지원 차량을 통합하기 위해 AODV 규칙을 확장한 연구는 다중 홉 통신 범위와 서비스 범위를 넓히는 방향을 제시하였다 [ref]. 또 다른 MANET 계열 연구는 노드별 사용 가능 통신 자원을 고려하여 AODV 기반 라우팅의 평균 수신율을 개선하는 방향을 제안하였다 [ref]. 이들 연구는 모두 라우팅 규칙의 수정이 성능에 중요함을 보여주지만, 제어 대상은 주로 전체 경로 선택 구조 또는 라우팅 확장 규칙 자체이다. 반면 본 연구의 제어 대상은 현재 차량이 RREP를 수신한 뒤 요청 노드 방향의 다음 차량으로 재전송할지 또는 현재 차량에서 중단할지를 결정하는 RREP 포워딩 규칙이다. 또한 기존 연구가 주로 경로 선택 구조 또는 네트워크 구조 적응을 다루는 반면, 본 연구는 현재 차량이 관측한 채널 상태와 현재 RREP 패킷의 전달 단계를 함께 사용하여 Channel Busy Percentage 재전송 허용 구간의 하한값과 상한값을 계산한다는 점에서 입력 정보와 출력 구조가 다르다.

두 번째 부류인 평가 환경 현실화 연구는 성능 지표 해석의 전제를 제공한다. 실제 도시 환경을 반영한 디지털 트윈 기반 VANET 시뮬레이션 연구는 단순 가상 도로 환경과 실제 도로 구조 기반 환경 사이에서 성능 차이가 크게 나타날 수 있음을 보였고, 차량 밀도와 동적 토폴로지 변화가 시뮬레이션 성능 지표에 큰 영향을 준다는 점을 강조하였다 [ref]. 이러한 결과는 단일 Channel Busy Percentage 값만으로 RREP 재전송 결과를 설명하기 어렵다는 본 연구의 문제의식과 직접 연결된다. 즉, 동일한 Channel Busy Percentage 값이 관측되더라도 같은 시각의 차량 밀도와 연결 구조가 다르면 최종 RREP 전달 결과가 달라질 수 있으므로, 현재 차량이 관측한 무선 채널 점유 수준, 현재 차량 주변의 이웃 차량 수, 그리고 현재 RREP 패킷에 기록된 hop count를 함께 반영하는 적응형 Channel Busy Percentage 재전송 허용 구간 규칙이 필요하다.

세 번째 부류인 차량 통신 보안 및 자원 처리 연구는 제어 대상은 다르지만 비교 축을 제공한다. 예를 들어, 차량이 직접 수행하던 CRL 관련 계산을 도로변 장치(Road Side Unit, RSU)로 이전하여 차량 측 계산 지연을 줄이는 연구는 지연 민감 환경에서 처리 위치가 성능에 직접 연결됨을 보였다 [ref]. 또 진화형 멀티미디어 브로드캐스트 멀티캐스트 서비스(evolved Multimedia Broadcast Multicast Service, eMBMS) 기반 CRL 배포 연구와 블록체인 기반 지역 CRL 연구는 데이터 전달 방식과 처리 구조 변경이 운용 성능을 개선할 수 있음을 보였다 [ref]. 이들 연구는 RREP 재전송 여부를 직접 다루지는 않지만, 차량 통신 환경에서 어느 시점에 어떤 처리 규칙을 적용하느냐가 최종 성능을 바꾼다는 점에서 본 연구와 문제 구조를 공유한다.

네 번째 부류인 V2X 메시지 및 플랫폼 연구는 상위 서비스 계층을 다룬다. 기본 안전 메시지(Basic Safety Message, BSM) 저장 및 조회 프레임워크 연구는 Event-Sourcing과 명령-조회 책임 분리(Command Query Responsibility Segregation, CQRS) 구조를 이용하여 메시지의 안전한 저장과 실시간 조회를 강조하였다 [ref]. 커넥티드 카 플랫폼 아키텍처 연구와 협대역 사물인터넷(NarrowBand-Internet of Things, NB-IoT) 기반 차량 관제 시스템 연구는 차량 정보 수집, 모니터링, 제어, 서비스 확장 구조를 중심으로 설명하였다 [ref]. 이들 연구는 데이터 관리와 서비스 계층 설계에는 유의미하지만, 라우팅 경로 형성 과정에서 현재 차량이 수신한 RREP를 다음 차량으로 재전송할지 또는 현재 차량에서 중단할지를 상태 적응적으로 결정하는 문제를 직접 다루지는 않는다.

정리하면, JKSCI에서 확인한 유사 연구들은 라우팅 규칙 확장, 평가 환경 현실화, 보안 처리 최적화, 메시지 및 플랫폼 구조라는 서로 다른 문제를 다룬다. 그러나 현재 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부를 함께 사용하여 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값을 동적으로 계산하고, 계산된 두 값을 현재 차량의 RREP 포워딩 결정에 직접 적용하는 구조는 이번에 확인한 유사 논문군에서 직접 확인되지 않았다. 따라서 본 연구는 기존 차량 네트워크 적응성 문제를 계승하면서도, RREP 포워딩 결정 단계에서 사용할 Channel Busy Percentage 재전송 허용 하한값과 상한값을 입력 조건별로 추정하는 문제로 구체화한다는 점에서 차별성을 가진다.

# 3. Preliminary

## 3.1 IEEE 802.11bd 기반 차량 통신 환경

IEEE 802.11bd는 차량 간 직접 통신과 차량-도로변 장치 간 통신을 지원하는 최신 차량 통신 표준이다. 이 표준은 고속 이동 환경에서도 패킷 전송 성능을 유지하기 위한 물리계층과 매체접근제어계층 기능을 제공한다. 그러나 실제 차량 운용 환경에서는 동일한 IEEE 802.11bd 기반 통신 설정을 사용하더라도 시각마다 차량 밀도, 도로 구간별 동시 전송 수, 차량 간 연결 구조가 달라진다. 따라서 한 시각에 관측한 채널 상태와 그 뒤에 나타나는 패킷 전달 결과의 관계도 시각마다 달라질 수 있다. 본 연구가 고정된 하나의 RREP 전달 기준 대신 시각별 Channel Busy Percentage 값, 시각별 이웃 차량 수, 시각별 hop count 값, 그리고 hop count 값이 1 이하인지 여부에 따라 달라지는 Channel Busy Percentage 재전송 허용 하한값과 상한값을 추정하려는 이유가 여기에 있다.

## 3.2 AODV의 RREQ/RREP 절차와 RREP 포워딩 결정의 의미

AODV는 경로가 필요할 때만 경로를 탐색하는 온디맨드 라우팅 프로토콜이다. 요청 노드는 RREQ를 송신하여 목적지까지 도달 가능한 경로를 찾고, 목적지 노드 또는 유효한 경로를 보유한 노드는 RREP를 생성하여 그 경로 정보를 역방향으로 전달한다. RREP는 여러 중간 차량을 거쳐 원래 RREQ를 보낸 요청 노드까지 도달해야 최종 경로 형성이 완료된다. 따라서 현재 차량이 수신한 RREP를 요청 노드 방향의 다음 차량으로 재전송할지, 아니면 현재 차량에서 중단할지를 결정하는 순간은 단순 중계 동작이 아니라 최종 경로 복원 성공 여부를 바꾸는 핵심 제어 지점이다.

본 연구에서 제어 대상은 AODV 전체 알고리즘이 아니라 현재 차량의 RREP 포워딩 결정이다. 즉, 본 연구는 RREQ 생성 규칙이나 전체 경로 선택 규칙을 새로 설계하는 것이 아니라, 이미 진행 중인 RREP 역방향 전달 과정에서 현재 차량이 수신한 RREP를 요청 노드 방향의 다음 차량으로 계속 재전송할지 또는 현재 차량에서 중단할지를 현재 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부의 조합에 따라 결정하는 규칙을 설계한다.

## 3.3 Channel Busy Percentage와 Channel Busy Percentage 재전송 허용 구간 기반 전달 규칙

본 연구는 현재 차량이 직접 측정한 채널 상태 지표로 Channel Busy Percentage를 사용한다. Channel Busy Percentage는 현재 차량이 관측한 무선 채널이 얼마나 오랫동안 점유되었는지를 나타내는 값이며, 현재 시각의 채널 혼잡 정도를 직접 반영한다. 학습 데이터 구성 단계에서는 현재 차량이 측정한 Channel Busy Percentage 값이 RREP 재포워딩 결정 사건 로그에 기록되어 있으며, 이웃 차량 수, AODV 라우팅 경로 설정 성공 횟수, AODV 라우팅 경로 설정 실패 횟수, AODV 라우팅 경로 설정 완료까지 걸린 평균 시간, 경로오류(Route Error, RERR) 발생 횟수, 라우팅 경로 무효화 횟수, 라우팅 경로 삭제 횟수는 차량별 1초 단위 네트워크 상태 집계 로그에서 가져와 차량 식별자와 정수 초 구간 기준으로 결합한다. 따라서 Channel Busy Percentage는 현재 차량의 직접 관측값이고, 나머지 성능 항목은 같은 차량의 같은 정수 초 구간에 대응하는 집계값이다.

본 연구가 사용하는 기본 RREP 포워딩 규칙은 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값으로 정의되는 허용 구간 규칙이다. 현재 차량이 관측한 Channel Busy Percentage 값이 Channel Busy Percentage 재전송 허용 하한값 이상이고 Channel Busy Percentage 재전송 허용 상한값 이하이면 현재 차량은 수신한 RREP를 요청 노드 방향의 다음 차량으로 재전송한다. 반대로 현재 차량이 관측한 Channel Busy Percentage 값이 허용 구간 밖에 있으면 현재 차량은 그 RREP를 재전송하지 않고 현재 차량에서 중단한다. 이 규칙은 식 (1)과 같이 표현할 수 있다.

$$
F_t = cases{ 1,~& l_t <= c_t <= u_t # 0,~& otherwise }
$$

식 (1)에서 $c_t$는 시각 $t$에 현재 차량이 관측한 Channel Busy Percentage 값이다. $l_t$와 $u_t$는 시각 $t$의 RREP 포워딩 결정에 적용되는 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값이다. $F_t=1$은 현재 차량이 수신한 RREP를 요청 노드 방향의 다음 차량으로 재전송함을 의미하고, $F_t=0$은 현재 차량이 그 RREP를 중단함을 의미한다. 본 연구가 Channel Busy Percentage 재전송 허용 구간의 경계값을 하한값과 상한값 두 개로 두는 이유는, 단순히 채널이 혼잡한 경우만 배제하는 것이 아니라 현재 차량이 측정한 채널 점유 수준이 RREP 재전송에 적합한 범위 안에 있는지를 구간 형태로 결정하기 위해서이다.

## 3.4 입력 변수 조합에 따른 Channel Busy Percentage 재전송 허용 하한값·상한값 추정 문제

동일한 Channel Busy Percentage 값이 관측되더라도 현재 차량 주변의 이웃 차량 수가 다르면 경쟁 차량 수가 달라질 수 있고, 현재 RREP 패킷에 기록된 hop count 값이 다르면 현재 RREP가 목적지 인접 전달 구간에 있는지 또는 다중 홉 전달 구간에 있는지가 달라질 수 있다. 따라서 같은 Channel Busy Percentage 값에 대해 항상 같은 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값을 적용하는 규칙은 충분하지 않을 수 있다. 본 연구는 이러한 현재 차량의 Channel Busy Percentage 값, 이웃 차량 수, hop count 값에 따라 RREP 재전송 적합성이 달라지는 성질을 반영하기 위해 현재 차량이 관측한 Channel Busy Percentage 값, 현재 차량이 인식한 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부를 입력으로 사용하여 Channel Busy Percentage 재전송 허용 구간의 하한값과 상한값을 출력하는 회귀모델을 학습한다.

# 4. 제안기법

본 장에서는 RREP 재포워딩 결정 사건 로그와 차량별 1초 단위 네트워크 상태 집계 로그를 이용해 입력 변수 범주별 학습 목표 Channel Busy Percentage 재전송 허용 하한값-상한값 조합을 생성하고, 이를 바탕으로 실제 RREP 처리 시각에 적용할 Channel Busy Percentage 재전송 허용 하한값과 상한값을 추정하는 방법을 설명한다. 설명 순서는 학습 데이터 구성, 점수 계산, 입력 변수 범주별 학습 목표 조합 선택, 회귀모델 학습, 실제 적용 규칙의 다섯 단계이다.

## 4.1 학습 데이터 구성과 입력 변수 정의

본 연구의 학습 샘플 기본 단위는 현재 차량이 수신한 RREP를 원래 RREQ를 보낸 요청 노드 방향의 다음 차량으로 재전송할지, 아니면 현재 차량에서 중단할지를 결정한 1회의 기록이다. 한 개의 학습 샘플은 차량 식별자 1개, RREP 포워딩 결정 시각 1개, 그리고 그 시각에 수행된 RREP 재포워딩 결정 1개에 대응한다. RREP 재포워딩 결정 사건 로그에는 현재 차량이 그 결정을 내릴 때 측정한 Channel Busy Percentage 값, 현재 RREP 패킷에 기록된 hop count 값, 실제 적용된 Channel Busy Percentage 재전송 허용 하한값, 실제 적용된 Channel Busy Percentage 재전송 허용 상한값이 기록되어 있다. 여기에 차량별 1초 단위 네트워크 상태 집계 로그에서 집계된 이웃 차량 수, AODV 라우팅 경로 설정 성공 횟수, AODV 라우팅 경로 설정 실패 횟수, AODV 라우팅 경로 설정 완료까지 걸린 평균 시간, 경로오류(Route Error, RERR) 발생 횟수, 라우팅 경로 무효화 횟수, 라우팅 경로 삭제 횟수를 결합하여 하나의 학습 샘플을 구성한다.

RREP 재포워딩 결정 사건 로그와 차량별 1초 단위 네트워크 상태 집계 로그를 하나의 학습 샘플로 묶기 위해 두 로그의 시간을 동일한 정수 초 기준으로 맞춘다. 먼저 현재 차량이 수신한 RREP를 다음 차량으로 재전송할지 또는 현재 차량에서 중단할지를 결정한 시각을 내림하여 정수 초로 변환한다. 예를 들어 결정 시각이 12.8초이면 12초 구간으로 처리한다. 이후 동일 차량의 동일 정수 초 구간에 해당하는 네트워크 상태 집계 로그를 대응시켜 이웃 차량 수, AODV 라우팅 경로 설정 성공 횟수, AODV 라우팅 경로 설정 실패 횟수, AODV 라우팅 경로 설정 완료까지 걸린 평균 시간, 경로오류(Route Error, RERR) 발생 횟수, 라우팅 경로 무효화 횟수, 라우팅 경로 삭제 횟수를 그 샘플에 부여한다. 이와 같은 정수 초 단위 결합을 사용하는 이유는 시뮬레이터 로그가 개별 RREP 포워딩 결정 1건마다 그 뒤에 발생한 라우팅 성능 변화를 직접 라벨로 제공하지 않기 때문이다. 따라서 본 연구는 동일 차량의 동일 정수 초 구간에서 함께 기록된 집계 지표를 개별 포워딩 결정 기록에 대응시키는 근사 라벨링 방식을 사용한다. 즉, 위 여섯 개 성능 지표는 개별 포워딩 결정 1건의 순수 인과 효과가 아니라, 그 결정이 속한 동일 차량의 동일 정수 초 구간을 대표하는 집계값으로 해석한다. 이 점은 개별 결정의 순수 효과를 분리하지 못한다는 한계를 가지지만, 현재 로그 구조 안에서 RREP 포워딩 결정과 후속 라우팅 상태를 같은 시간 축 위에서 연결하기 위한 현실적 방법이다.

전체 실험은 학습용 10개, 검증용 2개, 평가용 2개 실험으로 분리하여 사용한다. 학습에는 run 4, 10, 14, 15, 16, 17, 18, 19, 20, 28을 사용하고, 검증에는 run 31, 35를 사용하며, 평가에는 run 22, 25를 사용한다. 선정된 14개 실험에서 수집된 RREP 재포워딩 결정 기록은 전처리 조건을 만족하는 경우 학습·검증·평가에 사용한다. 이러한 실험 단위 분할은 학습과 평가가 동일 실험 결과에 과도하게 의존하지 않도록 하기 위한 설정이다.

전처리 과정에서는 필수 항목이 없는 샘플을 제거한다. 필수 항목은 RREP 포워딩 결정 시각, 차량 식별자, hop count 값, Channel Busy Percentage 값, 실제 적용된 Channel Busy Percentage 재전송 허용 하한값, 실제 적용된 Channel Busy Percentage 재전송 허용 상한값이다. 또한 hop count 값은 1 이상 6 이하인 샘플만 사용하고, 실제 적용된 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값은 반올림하여 정수값으로 변환한다. 실제 적용된 Channel Busy Percentage 재전송 허용 하한값이 실제 적용된 Channel Busy Percentage 재전송 허용 상한값보다 큰 샘플은 RREP 포워딩 규칙이 성립하지 않으므로 제외한다.

본 연구는 시각 $t$에서 현재 차량의 입력 변수를 $x_t=(c_t,n_t,h_t,d_t)$로 정의한다. 여기서 $c_t$는 현재 차량이 관측한 Channel Busy Percentage 값, $n_t$는 현재 차량이 인식한 이웃 차량 수, $h_t$는 현재 RREP 패킷에 기록된 hop count 값, $d_t$는 hop count 값이 1 이하인지 여부를 나타내는 이진 변수이다. 이진 변수 $d_t$는 식 (2)와 같이 정의한다.

$$
d_t = cases{ 1,~& h_t <= 1 # 0,~& h_t > 1 }
$$

식 (2)에서 $d_t=1$은 현재 RREP 패킷이 목적지 인접 전달 구간에 있음을 나타내고, $d_t=0$은 현재 RREP 패킷이 아직 둘 이상의 홉을 더 거쳐야 하는 다중 홉 전달 구간에 있음을 나타낸다. 즉, $d_t$는 위치 정보나 차량 이동 방향을 나타내는 변수가 아니라 현재 RREP 패킷의 전달 단계가 목적지 인접 전달 구간인지 여부를 구분하는 변수이다.

$c_t$는 현재 차량의 채널 점유 수준을 직접 반영하고, $n_t$는 현재 차량 주변의 잠재적 동시 전송 경쟁 차량 수를 반영한다. $h_t$는 현재 RREP 패킷이 역방향 전달 경로에서 어느 단계까지 진행되었는지를 나타내며, $d_t$는 목적지 인접 전달 구간인지 여부를 이진적으로 구분한다. 이후 4.3절에서 $c_t$와 $n_t$만 5 단위로 구간화하는 이유는 두 변수의 연속 범위가 넓어 원값을 그대로 사용하면 동일 조건 샘플 수가 지나치게 줄어들기 때문이다. 반면 $h_t$는 1 이상 6 이하의 좁은 정수 범위만 사용하므로 원값을 유지하고, $d_t$는 이미 이진 변수이므로 별도 구간화 없이 그대로 사용한다.

## 4.2 RREP 포워딩 결정 결과 점수 정의

본 연구는 현재 차량의 RREP 포워딩 결정이 단일 성능 지표만 바꾸는 것이 아니라, AODV 라우팅 경로 설정 성공 횟수, AODV 라우팅 경로 설정 실패 횟수, AODV 라우팅 경로 설정 완료까지 걸린 평균 시간, 경로오류(Route Error, RERR) 발생 횟수, 라우팅 경로 무효화 횟수, 라우팅 경로 삭제 횟수를 함께 바꿀 수 있다고 본다. 따라서 본 연구는 하나의 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값 조합의 품질을 평가하기 위해 위 여섯 개 성능 지표를 결합한 시각 $t$의 점수 $S_t$를 정의한다.

$$
S_t = alpha_1 R_t^{"succ"} - alpha_2 R_t^{"fail"} - alpha_3 D_t - alpha_4 E_t^{"rerr"} - alpha_5 E_t^{"inv"} - alpha_6 E_t^{"del"}
$$

식 (3)에서 $R_t^{"succ"}$는 동일 차량의 동일 정수 초 구간에서 집계된 AODV 라우팅 경로 설정 성공 횟수이고, $R_t^{"fail"}$는 동일 차량의 동일 정수 초 구간에서 집계된 AODV 라우팅 경로 설정 실패 횟수이다. $D_t$는 동일 차량의 동일 정수 초 구간에서 측정한 AODV 라우팅 경로 설정 완료까지 걸린 평균 시간이다. $E_t^{"rerr"}$는 동일 차량의 동일 정수 초 구간에서 발생한 경로오류(Route Error, RERR) 횟수, $E_t^{"inv"}$는 동일 차량의 동일 정수 초 구간에서 발생한 라우팅 경로 무효화 횟수, $E_t^{"del"}$는 동일 차량의 동일 정수 초 구간에서 발생한 라우팅 경로 삭제 횟수이다.

본 연구는 가중치를 식 (4)와 같이 설정한다.

$$
alpha_1 = 2.0, alpha_2 = 3.0, alpha_3 = 0.02, alpha_4 = 1.0, alpha_5 = 0.25, alpha_6 = 0.1
$$

식 (4)의 가중치를 식 (3)에 대입하면 최종 점수식은 식 (5)와 같다.

$$
S_t = 2.0 R_t^{"succ"} - 3.0 R_t^{"fail"} - 0.02 D_t - E_t^{"rerr"} - 0.25 E_t^{"inv"} - 0.1 E_t^{"del"}
$$

위 가중치 설정은 여섯 개 성능 지표의 역할과 수치 범위를 함께 고려한 설계이다. 본 연구는 이 계수들을 이론적으로 유일하게 도출된 값이나 최적화로 확정된 값으로 해석하지 않는다. 대신 학습 구간 로그에서 각 항목의 관측 범위와 중요도를 비교하여, 성공 증가는 보상하고 실패·오류·삭제 증가는 벌점으로 반영하되 어느 한 항목이 수치 범위만으로 전체 점수를 지배하지 않도록 수동 조정한 기준 계수로 사용한다. AODV 라우팅 경로 설정 성공 횟수는 최종 라우팅 경로 형성의 직접적 긍정 결과이므로 양의 가중치를 부여한다. AODV 라우팅 경로 설정 실패 횟수는 재탐색 오버헤드와 서비스 단절을 유발할 수 있으므로 더 큰 절댓값의 음의 가중치를 부여한다. AODV 라우팅 경로 설정 완료까지 걸린 평균 시간은 연속값이고 수치 범위가 크므로 작은 계수를 부여한다. 경로오류(Route Error, RERR) 발생 횟수, 라우팅 경로 무효화 횟수, 라우팅 경로 삭제 횟수는 모두 라우팅 경로 불안정성을 나타내므로 음의 가중치를 부여한다. 따라서 식 (5)의 점수가 클수록 현재 차량의 RREP 포워딩 결정과 함께 관측된 여섯 개 성능 지표 조합이 더 바람직하다고 해석한다.

## 4.3 입력 변수 범주별 학습 목표 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 선택

학습 데이터의 입력 변수는 연속값이므로, Channel Busy Percentage 값, 이웃 차량 수, hop count 값, 그리고 hop count 값이 1 이하인지 여부가 서로 다른 기록을 한꺼번에 비교하면 입력 조건 차이와 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 차이가 뒤섞일 수 있다. 따라서 본 연구는 Channel Busy Percentage 값, 이웃 차량 수, hop count 값, 그리고 hop count 값이 1 이하인지 여부가 동일하거나 매우 가까운 기록끼리 비교하기 위해 입력 변수를 이산화하여 입력 변수 범주를 구성한다.

본 연구는 Channel Busy Percentage 값과 이웃 차량 수를 각각 5 단위로 구간화한다. 이때 5로 나눈 뒤 얻은 구간 번호를 사용하지 않고, 각 5 단위 구간의 대표값을 상태값으로 사용한다. 이를 위해 시각 $t$의 Channel Busy Percentage 값과 이웃 차량 수에 대해 식 (6-a)와 식 (6-b)의 구간 대표값을 정의한다.

$$
q_c(t) = 5 left lfloor {c_t over 5} right rfloor
$$

$$
q_n(t) = 5 left lfloor {n_t over 5} right rfloor
$$

$q_c(t)$는 현재 차량이 관측한 Channel Busy Percentage 값 $c_t$가 속한 5 단위 구간의 대표값이고, $q_n(t)$는 현재 차량이 인식한 이웃 차량 수 $n_t$가 속한 5 단위 구간의 대표값이다. 예를 들어 $c_t$가 0 이상 4 이하이면 $q_c(t)=0$이고, $c_t$가 5 이상 9 이하이면 $q_c(t)=5$이다. 이웃 차량 수 $n_t$에 대해서도 같은 방식으로 0, 5, 10과 같은 5 단위 대표값을 부여한다. 구현에서는 두 값 모두 100을 넘지 않도록 제한한다. 5 단위 이산화는 Channel Busy Percentage 값과 이웃 차량 수를 너무 세밀하게 나누면 같은 범주에 속하는 샘플 수가 급격히 줄어들고, 반대로 너무 넓게 묶으면 서로 다른 전송 환경이 한 범주에 섞이므로 사용한다. hop count 값은 반올림 후 1 이상 6 이하 범위로 제한하여 사용하고, 앞서 정의한 이진 변수 $d_t$를 함께 사용한다. 따라서 시각 $t$의 입력 변수 범주 $s_t$는 식 (6-c)와 같이 정의한다.

$$
s_t = ( q_c(t), q_n(t), h_t, d_t )
$$

시각 $t$에서 실제 적용된 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값을 각각 $l_t$, $u_t$로 표기하면, 본 연구는 각 입력 변수 범주 안에서 로그에 실제로 등장한 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 $(l,u)$만을 비교 대상으로 사용한다. 즉, 관측되지 않은 모든 Channel Busy Percentage 재전송 허용 하한값-상한값 조합을 새로 생성하여 탐색하는 것이 아니라, 같은 입력 변수 범주 안에서 실제 적용 이력이 있는 Channel Busy Percentage 재전송 허용 하한값-상한값 조합들만 비교한다. 입력 변수 범주 $s$와 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 $(l,u)$에 대한 평균 점수는 식 (6)과 같이 계산한다.

$$
bar S(s,l,u) = {1} over {N(s,l,u)} sum_{t in OMEGA(s,l,u)} S_t
$$

식 (6)에서 $OMEGA(s,l,u)$는 입력 변수 범주 $s$에 속하면서 Channel Busy Percentage 재전송 허용 하한값이 $l$이고 Channel Busy Percentage 재전송 허용 상한값이 $u$였던 모든 RREP 포워딩 결정 기록의 집합이다. $N(s,l,u)$는 그 기록 집합의 크기이며, 입력 변수 범주 $s$와 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 $(l,u)$가 동시에 같은 기록 수를 의미한다.

본 연구는 기록 수가 너무 적은 Channel Busy Percentage 재전송 허용 하한값-상한값 조합이 우연한 결과로 선택되는 것을 줄이기 위해 식 (7)의 최소 기록 수 조건을 적용한다.

$$
N(s,l,u) >= 5
$$

입력 변수 범주 $s$에서 관측된 Channel Busy Percentage 재전송 허용 하한값-상한값 조합들 가운데 가장 높은 평균 점수는 식 (8)과 같이 정의한다.

$$
bar S_max(s) = max_{l,u} bar S(s,l,u)
$$

입력 변수 범주 $s$의 각 Channel Busy Percentage 재전송 허용 하한값-상한값 조합이 최고 평균 점수와 얼마나 차이 나는지는 식 (9)로 계산한다.

$$
DELTA(s,l,u) = bar S_max(s) - bar S(s,l,u)
$$

본 연구는 최고 평균 점수를 기록한 조합 하나만 기계적으로 선택하지 않고, 최고 평균 점수와의 차이가 작은 조합들을 먼저 남긴다. 그 이유는 1초 단위 집계 결과에 포함될 수 있는 잡음을 완충하고 입력 변수 범주별로 지나치게 불안정한 단일 선택을 피하기 위해서이다. 이를 위해 식 (10)의 조건을 적용한다. 여기서 0.2는 최고 평균 점수와 사실상 유사한 성능으로 볼 수 있는 후보군만 남기기 위한 실용적 허용폭이다.

$$
DELTA(s,l,u) <= 0.2
$$

따라서 입력 변수 범주 $s$에서 학습 목표값 후보로 남기는 Channel Busy Percentage 재전송 허용 하한값-상한값 조합 집합은 식 (11)과 같이 정의한다.

$$
C(s) = { (l,u) | N(s,l,u) >= 5, DELTA(s,l,u) <= 0.2 }
$$

후보 집합 $C(s)$가 정해지면 본 연구는 사전식 정렬 규칙으로 학습 목표값으로 사용할 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값 조합 1개를 선택한다. 정렬 우선순위는 다음과 같다. 첫째, Channel Busy Percentage 재전송 허용 하한값이 큰 조합을 우선한다. 둘째, 평균 점수가 큰 조합을 우선한다. 셋째, 기록 개수가 많은 조합을 우선한다. 넷째, Channel Busy Percentage 재전송 허용 상한값과 Channel Busy Percentage 재전송 허용 하한값의 차이가 작은 조합을 우선한다. 다섯째, Channel Busy Percentage 재전송 허용 상한값이 작은 조합을 우선한다.

위 정렬 규칙은 전체 후보 집합의 성능 우열을 새로 정의하기 위한 규칙이 아니라, 최고 평균 점수와의 차이가 0.2 이하인 후보들 가운데 학습 목표값으로 사용할 조합 1개를 고르기 위한 규칙이다. Channel Busy Percentage 재전송 허용 하한값을 우선적으로 크게 두는 이유는 채널이 지나치게 비어 있는 경우까지 무조건 RREP 재전송을 허용하지 않기 위해서이다. 평균 점수와 기록 개수를 뒤따라 고려하는 이유는 평균 점수가 크고 기록 수가 충분한 조합을 우선하여 우연한 선택 가능성을 줄이기 위해서이다. 상한값과 하한값의 차이가 작은 조합을 우선하는 이유는 재전송 허용 구간이 과도하게 넓어지는 상황을 줄이기 위해서이다. 상한값이 작은 조합을 마지막 기준으로 두는 이유는 비슷한 평균 점수를 보이는 조합들 가운데 지나치게 높은 채널 점유 수준까지 허용하는 조합보다 더 보수적인 상한을 가진 조합을 선택하기 위해서이다. 즉, 이 규칙은 최고 평균 점수 부근 후보들 가운데 상대적으로 보수적인 재전송 정책을 선택하기 위한 운용 규칙이다.

위 선택 과정을 통해 입력 변수 범주 $s$에 대응하는 학습 목표 Channel Busy Percentage 재전송 허용 하한값과 학습 목표 Channel Busy Percentage 재전송 허용 상한값을 각각 $l_s^\ast$와 $u_s^\ast$로 정의한다. 이후 회귀모델은 각 샘플이 속한 입력 변수 범주에 대해 입력 변수 범주별로 선택된 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값을 예측하도록 학습된다.

## 4.4 회귀모델 학습과 목표값 예측 정확도 평가

입력 변수 범주별 학습 목표 Channel Busy Percentage 재전송 허용 하한값과 상한값을 테이블 조회 방식으로만 사용하면, 실제 RREP 처리 시각에 연속적으로 변하는 입력값에 즉시 대응하기 어렵다. 따라서 본 연구는 입력 변수 범주별 학습 목표 조합을 목표로 하는 회귀모델을 학습하여 현재 입력값으로부터 Channel Busy Percentage 재전송 허용 하한값과 상한값을 직접 추정한다. 회귀모델을 사용하는 이유는 Channel Busy Percentage 값, 이웃 차량 수, hop count 값, 목적지 인접 여부 사이의 비선형 상호작용을 반영하면서도 입력값이 5 단위 경계 근처에서 조금 달라지는 경우에 연속적으로 대응할 수 있기 때문이다.

회귀모델의 입력은 $x_t=(c_t,n_t,h_t,d_t)$이고, 출력은 시각 $t$에 적용할 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값이다. 모델 출력은 식 (12)와 같이 표현한다.

$$
hat y_t = f_theta(x_t) = ( hat l_t, hat u_t )
$$

식 (12)에서 $hat l_t$와 $hat u_t$는 회귀모델이 예측한 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값이다. 회귀모델의 학습 목표값은 식 (13)과 같이 샘플 $t$가 속한 입력 변수 범주 $s_t$에 대응하는 학습 목표 Channel Busy Percentage 재전송 허용 하한값-상한값 조합으로 둔다.

$$
y_t = ( l_{s_t}^*, u_{s_t}^* )
$$

식 (13)은 동일한 입력 변수 범주에 속한 샘플들이 동일한 학습 목표 Channel Busy Percentage 재전송 허용 하한값과 동일한 학습 목표 Channel Busy Percentage 재전송 허용 상한값을 공유한다는 뜻이다.

학습 전에 입력 4개와 출력 2개를 각각 독립적으로 표준화한다. 이 전처리 단계는 서로 다른 값 범위를 갖는 변수들을 동일한 학습 과정에서 안정적으로 다루고, 두 출력값의 스케일 차이가 손실 계산에 편향을 주는 문제를 줄이기 위한 것이다.

본 연구는 회귀모델로 다층 퍼셉트론(Multi-Layer Perceptron, MLP)을 사용한다. 입력 차원 수는 작지만 입력 변수 사이의 결합 효과가 선형 관계로 충분히 설명되지 않을 수 있기 때문이다. 모델 구조는 입력층 4개, 은닉층 256개-256개-128개, 출력층 2개로 구성한다. 이 구조는 과도하게 깊지 않으면서도 비선형 결합을 학습할 수 있는 폭을 확보하기 위한 설정이다. 은닉층 활성화 함수는 ReLU를 사용하고, 손실함수는 평균제곱오차(Mean Squared Error, MSE)를 사용한다.

$$
L(theta) = {1} over {T} sum_{t=1}^{T} || f_theta(x_t) - y_t ||_2^2
$$

최적화는 학습률 $1\times10^{-3}$의 Adam을 사용한다. 학습은 최대 40 epoch까지 수행하고, 배치 크기는 4096으로 설정한다. 또한 검증 손실 기준 조기 종료를 적용하여 6 epoch 동안 성능이 개선되지 않으면 학습을 중단하고, 3 epoch 동안 개선이 없으면 학습률을 0.5배로 줄이며 최소 학습률은 $1\times10^{-5}$로 둔다. 이 설정은 대용량 샘플을 안정적으로 처리하면서 초기 수렴 속도와 과적합 억제 사이의 균형을 맞추기 위한 것이다. 회귀모델의 직접 학습 목표값은 각 샘플이 속한 입력 변수 범주에 대해 4.3절에서 선택한 $l_s^\ast$와 $u_s^\ast$이다. 실제 로그에 기록된 Channel Busy Percentage 재전송 허용 하한값과 상한값은 $l_s^\ast$와 $u_s^\ast$를 구성하기 위한 원자료로 사용한다.

평가는 샘플 단위 평가와 입력 변수 범주 단위 평가로 나누어 수행한다. 이때 학습 구간에서 생성한 teacher table과 상태키가 일치하는 검증·평가 샘플만 남긴 뒤 평가를 수행한다. 샘플 단위 평가는 남은 평가 샘플 각각에 대해 예측값과 목표값을 직접 비교하여 Channel Busy Percentage 재전송 허용 하한값과 상한값 각각의 결정계수 $R^2$와 평균절대오차(MAE)를 계산하는 방식이다. 입력 변수 범주 단위 평가는 동일한 입력 변수 범주에 속한 평가 샘플들의 예측값을 평균한 뒤, 그 평균 예측값을 입력 변수 범주별 학습 목표 조합과 비교하는 방식이다. 샘플 단위 평가는 개별 예측 오차를 확인하기 위한 것이고, 입력 변수 범주 단위 평가는 동일한 입력 변수 범주 안에서 예측값이 목표 조합에 얼마나 수렴하는지 확인하기 위한 것이다. 여기서 수행하는 평가는 회귀모델이 입력 변수 범주별 학습 목표 조합을 얼마나 정확하게 근사하는지 평가하는 절차이며, 실제 네트워크 성능 비교는 다음 실험 장에서 별도로 수행한다.

## 4.5 Channel Busy Percentage 재전송 허용 하한값-상한값 후처리와 실제 RREP 적용 규칙

회귀모델이 출력한 $hat l_t$와 $hat u_t$는 연속값이므로 학습 데이터 범위를 벗어나는 값이 나올 수 있고, 두 값의 순서나 간격이 실제 제어 규칙에 맞지 않을 수도 있다. 따라서 본 연구는 회귀모델 출력값에 범위 제한과 최소 간격 조건을 적용한 뒤 최종 Channel Busy Percentage 재전송 허용 하한값과 상한값으로 사용한다. 구현에서는 이 후처리 상수들을 학습된 모델 가중치와 함께 시뮬레이터 설정값으로 내보낸다.

먼저 Channel Busy Percentage 재전송 허용 하한값과 Channel Busy Percentage 재전송 허용 상한값에 공통 허용 범위를 적용한다. 식 (15)와 식 (16)에서 $L_{min}$과 $L_{max}$는 공통 하한과 공통 상한이며, 본 연구는 각각 0과 100을 사용한다.

$$
bar l_t = min { L_max, max { L_min, hat l_t } }
$$

$$
bar u_t = min { L_max, max { L_min, hat u_t } }
$$

위 범위 제한은 회귀모델 출력이 비현실적으로 작은 값이나 큰 값으로 벗어나는 상황을 막기 위한 단계이다. 다음으로 하한값과 상한값 사이에 최소 간격 조건을 적용한다. $delta_{min}$은 Channel Busy Percentage 재전송 허용 하한값과 상한값 사이에 유지해야 하는 최소 차이이며, 본 연구는 $delta_{min}=5$를 사용한다. 최소 간격을 5로 두는 이유는 4.3절에서 Channel Busy Percentage 값을 5 단위로 이산화하였기 때문에 후처리 단계에서도 최소 허용 구간 폭을 같은 5 단위 기준으로 유지하기 위해서이다.

$$
tilde l_t = bar l_t
$$

$$
tilde u_t = max { bar u_t, tilde l_t + delta_min }
$$

위 최소 간격 보정은 Channel Busy Percentage 재전송 허용 상한값이 하한값보다 충분히 크도록 보장하여 재전송 허용 구간이 사라지거나 지나치게 좁아지는 상황을 방지하기 위한 단계이다. 보정이 끝난 $tilde l_t$와 $tilde u_t$가 현재 차량의 실제 RREP 포워딩 결정에 사용하는 최종 Channel Busy Percentage 재전송 허용 하한값과 상한값이다. 본 연구가 사용하는 후처리 상수는 $L_{min}=0$, $L_{max}=100$, $delta_{min}=5$이다.

최종 RREP 포워딩 결정은 식 (18)과 같이 수행한다.

$$
Forward_t = cases{ 1,~& tilde l_t <= c_t <= tilde u_t # 0,~& otherwise }
$$

식 (18)은 현재 차량이 관측한 Channel Busy Percentage 값 $c_t$가 최종 Channel Busy Percentage 재전송 허용 하한값 $tilde l_t$ 이상이고 최종 Channel Busy Percentage 재전송 허용 상한값 $tilde u_t$ 이하이면 현재 차량이 수신한 RREP를 요청 노드 방향의 다음 차량으로 재전송하고, 그렇지 않으면 현재 차량에서 중단한다는 뜻이다. 즉, 회귀모델은 RREP 재전송 여부를 직접 출력하지 않고, 현재 입력 조건에 대응하는 Channel Busy Percentage 재전송 허용 하한값과 상한값을 출력한다. 실제 RREP 재전송 여부는 현재 차량이 측정한 Channel Busy Percentage 값이 그 두 값 사이에 위치하는지 여부로 결정한다.

정리하면, 본 연구는 기본 AODV에 Channel Busy Percentage 기반 RREP 포워딩 규칙을 추가하고, 현재 차량이 관측한 Channel Busy Percentage 값, 이웃 차량 수, 현재 RREP 패킷에 기록된 hop count 값, 그리고 hop count 값이 1 이하인지 여부를 함께 사용하여 시각별 Channel Busy Percentage 재전송 허용 하한값과 상한값을 계산한다. 그리고 계산된 두 값을 현재 차량이 측정한 Channel Busy Percentage 값과 비교함으로써 각 시각의 입력 조건에 맞는 RREP 포워딩 결정을 수행한다.
