# 1. 인터넷컴퓨팅

## 1. 클라우드 컴퓨팅과 엣지 컴퓨팅

### 문제

클라우드 컴퓨팅(Cloud Computing)과 엣지 컴퓨팅(Edge Computing)의 개념과 주요 특징을 각각 설명하고, 두 컴퓨팅 방식의 차이점을 처리 위치, 지연시간, 네트워크 의존성 측면에서 비교하시오.

### 암기용 답안

클라우드 컴퓨팅은 원격 데이터센터의 자원을 필요에 따라 제공받는 방식으로, 대규모 저장·처리와 자원 확장에 유리하다.
엣지 컴퓨팅은 데이터 발생 장치나 가까운 서버에서 처리하는 방식으로, 빠른 응답에 유리하지만 자원이 제한적이다.
클라우드는 원격 통신으로 지연과 네트워크 의존성이 커질 수 있고, 엣지는 현장 처리로 지연과 외부망 의존성을 줄일 수 있다.

**암기 키워드: 클라우드 = 원격·대규모·확장 / 엣지 = 현장·저지연·외부망 의존 감소**

## 2. RESTful API

### 문제

인터넷 기반 응용 서비스에서 RESTful API의 개념과 동작 원리를 설명하시오.

### 암기용 답안

RESTful API는 자원을 URI로 식별하고 통일된 인터페이스로 자원의 표현을 주고받는 방식이다.
웹에서는 GET으로 조회, POST로 생성 등의 처리, PUT으로 대체, DELETE로 삭제를 요청한다.
서버는 요청을 처리한 뒤 상태 코드와 JSON 등의 데이터를 응답한다.
각 요청은 필요한 정보를 포함하여 이전 요청의 세션 맥락에 의존하지 않는 무상태성을 따른다.

**암기 키워드: URI로 자원 식별 → HTTP로 요청 → 상태 코드·데이터 응답 / 무상태**

# 2. 고급유비쿼터스컴퓨팅

## 1. 상황인지 컴퓨팅

### 문제

유비쿼터스 컴퓨팅 환경에서 Context-Aware Computing(상황인지 컴퓨팅)의 개념을 설명하고, 상황정보의 수집·처리·추론·서비스 제공 과정을 설명하시오.

### 암기용 답안

상황인지 컴퓨팅은 위치, 시간, 사용자 활동 등의 정보를 활용하여 현재 상황에 맞는 서비스를 제공하는 방식이다.
센서 등으로 정보를 수집하고, 잡음 제거와 데이터 통합으로 처리한 뒤, 규칙이나 기계학습으로 상황을 추론하여 적절한 서비스를 제공한다.
예를 들어 사람의 존재와 주변 밝기를 감지하여 ‘사람이 있고 어둡다’고 판단하면 조명을 자동으로 켠다.

**암기 키워드: 수집 → 처리 → 추론 → 서비스 / 사람 있음 + 어두움 → 조명 켜기**

## 2. Edge/Fog Computing의 필요성과 장단점

### 문제

IoT 및 유비쿼터스 컴퓨팅 환경에서는 다수의 센서와 디바이스에서 지속적으로 데이터가 발생한다. 이러한 환경에서 Edge/Fog Computing이 필요한 이유를 설명하고, 기존의 중앙집중형 Cloud Computing과 비교하여 지연시간, 네트워크 트래픽, 확장성, 개인정보 보호 측면에서 장점과 한계를 논하시오.

### 암기용 답안

Edge/Fog는 단말 주변이나 중간 노드에서 데이터를 분산 처리하여, 모든 데이터를 중앙 클라우드로 보낼 때의 지연과 통신 부담을 줄이기 위해 필요하다.
지연시간과 트래픽 측면에서는 현장 처리와 필요한 결과만의 전송이 유리하지만, 노드 과부하와 동기화 통신이 한계이다.
확장성 측면에서는 노드를 추가하여 부하를 분산할 수 있지만, 클라우드보다 분산 장치의 관리가 복잡하다.
개인정보 측면에서는 원시 데이터를 현장에 유지하여 외부 노출을 줄일 수 있지만, 여러 현장 장치의 보안을 각각 관리해야 한다.

**암기 키워드: 지연·트래픽 감소 / 분산 확장·관리 복잡 / 현장 보관·장치 보안**
