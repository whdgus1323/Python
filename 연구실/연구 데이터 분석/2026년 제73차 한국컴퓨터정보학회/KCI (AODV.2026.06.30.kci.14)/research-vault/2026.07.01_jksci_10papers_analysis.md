# JKSCI 유사 주제 논문 10편 분석

## 1. 분석 목적

이 문서는 Journal of The Korea Society of Computer and Information (JKSCI)에서 확보한 유사 주제 논문 10편을 대상으로, 다음 항목을 중심으로 공통 패턴과 차이를 정리한 결과이다.

- 논문 구조
- 문제 제기 논리
- 문맥과 맥락 구성
- 표현 방식
- 명확성 레벨
- 신뢰도
- 데이터와 검증 방식

이 문서의 목적은 단순 목록 정리가 아니라, 현재 작성 중인 사용자 논문이 JKSCI 계열 논문과 비교해 어떤 지점에서 더 맞닿아 있고, 어떤 지점에서 서술 전략을 달리 가져가야 하는지 판단할 수 있도록 기준을 만드는 데 있다.

## 2. 자료 확보 범위와 해석 한계

이번 분석은 각 논문의 JKSCI 기사 페이지에서 확보한 다음 정보에 근거한다.

- 제목
- 연도, 권호, DOI
- 초록(abstract)
- 일부 논문에 대해 확보된 기사 페이지 본문 일부와 참고문헌 노출 구간

따라서 아래 판단은 세 층위로 구분해야 한다.

- 직접 확인 가능 항목
  - 제목, 연도, 권호, DOI, 초록에 직접 드러나는 연구 문제, 제안 요소, 검증 방식
- 제한적으로 추정 가능한 항목
  - 초록의 서술 순서로부터 읽히는 논리 전개 방식
  - 초록 수준에서 확인되는 문맥과 맥락 연결 수준
- 이번 자료만으로 확정할 수 없는 항목
  - 본문 전체 절 구성
  - 수식 전개 방식
  - 표와 그림의 실제 배치
  - 실험 설정의 세부 변수, 데이터셋 크기, 통계 검정 여부

즉, 이 문서는 10편 전체를 완독한 뒤 쓴 본문 구조 분석이 아니라, 확보 가능한 기사 페이지와 초록 중심의 비교 분석이다. 따라서 구조, 논리, 문맥, 맥락, 표현, 명확성에 관한 판단은 초록과 메타데이터에 강하게 근거하고, 본문 전체 절 구조에 대한 단정은 피한다.

## 4. 논문별 개별 분석

아래 평가는 초록과 기사 페이지 메타데이터에서 직접 확인된 내용만 반영한다.

### 4.1 A Study on an Extended AODV Protocol for Integrating Non-SDN Vehicles into SDN-Enabled VANETs

- 구조
  - 초록 구조는 VANET 환경 설명 → 기존 SDN 적용 연구의 한계 → 비 SDN 차량 통합 문제 제기 → 확장 AODV 제안 → 시뮬레이션 검증 순서로 정리된다.
- 논리
  - 문제 설정과 제안 기법의 연결이 가장 직접적이다. 특히 기존 SDN 기반 접근이 비 SDN 차량에는 적용되지 않는다는 한계를 먼저 분리한 뒤, 표준 AODV 확장으로 해결책을 제시한다.
- 문맥과 맥락
  - VANET의 동적 특성과 단속 연결성이라는 상위 맥락을 먼저 제시하고, 그 뒤에 SDN 적용의 범위 제한을 문제 지점으로 좁힌다.
- 표현
  - 문제 대상, 한계 대상, 제안 대상이 비교적 선명하다.
- 명확성 레벨
  - 초록 기준으로는 높은 편이다. 다만 QoS provisioning의 구체 범위는 초록만으로는 확인되지 않는다.
- 신뢰도
  - 시뮬레이션 검증을 명시한다. 다만 어떤 시나리오와 지표를 썼는지는 초록만으로 확인되지 않는다.
- 데이터와 검증
  - VANET environment modeling과 performance simulations를 수행했다고 직접 명시한다.
- 사용자 논문과의 거리
  - AODV 확장, VANET, 다중 홉 전달이라는 점에서 가장 가깝다. 다만 현재 사용자 논문은 RREP forwarding threshold 제어에 더 초점을 둔다.

### 4.2 A Digital Twin-based Approach for VANET Simulation in Real Urban Environments

- 구조
  - 기존 시뮬레이터 검토 → OSM, SUMO, OMNeT++ 조합 선택 → 단순 가상 도로와 실제 도시환경 비교 시뮬레이션 → 성능 차이 확인 순서다.
- 논리
  - 왜 현실 도로환경이 필요한지를 비교 실험 결과로 뒷받침하는 구조다.
- 문맥과 맥락
  - 단순 시뮬레이션 환경이 실제 VANET 성능을 충분히 반영하지 못한다는 실험 맥락이 분명하다.
- 표현
  - 도구 선택 이유와 실험 비교 목적이 분리되어 있어 읽기 쉽다.
- 명확성 레벨
  - 중상 수준이다. 다만 어떤 성능 지표를 비교했는지는 초록에 구체적으로 나와 있지 않다.
- 신뢰도
  - 단순 주장보다 비교 실험 결과를 통해 필요성을 제시한다는 점에서 신뢰도가 높다.
- 데이터와 검증
  - simple virtual road environments와 realistic road environments를 비교했다는 점은 직접 확인된다.
- 사용자 논문과의 거리
  - 사용자 논문의 시뮬레이션 환경 설계와 맥락 서술에는 매우 유용하다. 그러나 라우팅 제어 기준 자체보다는 평가 무대 설정에 더 가깝다.

### 4.3 BSM framework using Event-Sourcing and CQRS pattern in V2X environment

- 구조
  - V2X와 C-ITS 표준 서비스 배경 → BSM의 역할 설명 → 저장 및 조회 프레임워크 제안 → 보안성과 실시간 조회 장점 제시 순서다.
- 논리
  - 통신 메시지 저장과 상태 재현이라는 응용 시스템 문제에 맞춰 프레임워크를 제안한다.
- 문맥과 맥락
  - 5G, 인공지능, 자율주행 시스템이라는 넓은 기술 맥락을 먼저 제시한다.
- 표현
  - 시스템 프레임워크 논문답게 구성 요소와 기능 장점을 나열하는 방식이 강하다.
- 명확성 레벨
  - 개념 설명은 비교적 명확하나, 성능 검증 지표보다 기능적 장점 설명 비중이 높다.
- 신뢰도
  - 안전 저장, 실시간 확인, 상태 재현을 주장하지만 초록만으로는 정량적 성능 검증이 얼마나 깊은지 확인하기 어렵다.
- 데이터와 검증
  - 초록에는 구현 또는 실험 환경의 구체 데이터가 직접 드러나지 않는다.
- 사용자 논문과의 거리
  - 라우팅 제어 자체보다는 V2X 메시지 프레임워크 측면에서 주변 맥락 참고용이다.

### 4.4 Efficient Cache Management Scheme with Maintaining Strong Data Consistency in a VANET

- 구조
  - VANET 정의 → 기존 cooperative caching scheme의 weak consistency 한계 → adaptive scheduling 기반 기법 제안 → simulation result 제시 순서다.
- 논리
  - 기존 방식의 제약을 먼저 지적하고, 그 뒤에 scheduling과 invalidation report 처리 방식을 통해 성능 개선을 주장한다.
- 문맥과 맥락
  - VANET을 mobile ad-hoc network의 차량 특화 형태로 먼저 정의한다. 즉 상위 개념을 먼저 열고 세부 문제로 들어간다.
- 표현
  - 비교적 고전적인 JKSCI 스타일이다. 문제, 기존 방식, 제안, 성능 결과가 짧게 이어진다.
- 명확성 레벨
  - 초록 기준으로는 중간 수준이다. 핵심 용어는 나오지만 입력 조건과 적용 범위는 세세하게 풀지 않는다.
- 신뢰도
  - simulation result가 있다고 명시한다. 다만 실험 데이터 규모와 설정값은 초록에서 확인되지 않는다.
- 데이터와 검증
  - query delay와 communication overhead를 비교 지표로 사용했다는 점은 직접 확인된다.
- 사용자 논문과의 거리
  - VANET에서 상태 기반 의사결정 또는 자원 관리가 성능 지표에 어떤 영향을 주는지 설명할 때 참고가 된다.

### 4.5 Certificate Revocation Scheme based on the Blockchain for Vehicular Communications

- 구조
  - Regional CRL 개념 설명 → 차량 위치 파악의 어려움 제시 → short-lived pseudonym과 blockchain 기반 기법 제안 → 분석 결과 제시 순서다.
- 논리
  - CRL 크기 축소와 privacy preserving 요구를 동시에 다루는 문제 구조다.
- 문맥과 맥락
  - 차량 통신의 보안 운영 문제를 먼저 제시하고, 위치 정보와 지역 단위 취소목록 구성이라는 운영 세부 과제로 내려간다.
- 표현
  - 보안 논문답게 문제 변수와 운영 조건을 비교적 직접적으로 쓴다.
- 명확성 레벨
  - 중상 수준이다. location privacy preserving, database query time, on-board unit라는 성능 및 운용 대상이 분명하다.
- 신뢰도
  - analysis results를 명시한다. 다만 실험인지 이론 분석인지, 시뮬레이션인지의 범위는 초록만으로는 한정적이다.
- 데이터와 검증
  - CRL size, database query time이 성능 지표로 직접 제시된다.
- 사용자 논문과의 거리
  - 라우팅 기법 논문은 아니지만, vehicular communications에서 문제 설정과 평가 지표를 기술하는 방식은 참고 가치가 있다.

### 4.6 A CRL Distribution Scheme Minimizing the Time for CRL Processing of Vehicles on Vehicular Communications

- 구조
  - CRL 필요성 설명 → 기존 scheme의 computational load 한계 → RSU가 linkage value 계산을 대신 수행하는 기법 제안 → simulation results 제시 순서다.
- 논리
  - 지연 민감형 응용에서 차량 측 계산 부담이 문제라는 점을 먼저 설정하고, 계산 위치를 RSU로 이동시키는 방식으로 해결한다.
- 문맥과 맥락
  - life-critical applications under 50msec latency라는 상위 응용 제약을 먼저 제시한다는 점이 특징이다.
- 표현
  - 성능 지표와 제약 조건이 비교적 수치적으로 제시된다.
- 명확성 레벨
  - 높은 편이다. 왜 기존 방식이 문제인지, 제안 기법이 어디에서 계산을 수행하는지 분명하다.
- 신뢰도
  - simulation results를 명시하고, latency-sensitive application impact라는 평가 목적을 분명히 둔다.
- 데이터와 검증
  - CRL processing time, computational load, low latency application impact가 직접적인 검증 포인트다.
- 사용자 논문과의 거리
  - 사용자 논문이 RREP 전달 판단과 지연 민감성의 연관을 강조할 때 참고할 수 있는 논리 구조를 제공한다.

### 4.7 A Certificate Revocation List Distribution Scheme over the eMBMS for Vehicular Networks

- 구조
  - certificate와 CRL의 필요성 → large CRL의 timely distribution 문제 → LTE eMBMS 기반 scheme 제안 → ns-3 simulation 분석 순서다.
- 논리
  - 기존 unicast 기반 배포의 비효율을 지적하고 multicast 기반 배포가 더 resource efficient하다고 주장한다.
- 문맥과 맥락
  - vehicular networks에서 trustworthiness verification이라는 상위 목적을 먼저 둔다.
- 표현
  - 통신 자원 효율성과 latency, execution time을 핵심 평가 축으로 삼는다.
- 명확성 레벨
  - 중상 수준이다. 다만 MBMSFN coverage 변화가 실제 어떤 시나리오로 구성되었는지는 초록만으로는 알 수 없다.
- 신뢰도
  - ns-3 simulation을 직접 언급하므로 검증 방법은 비교적 명확하다.
- 데이터와 검증
  - performance, latency, execution time을 varying coverage 조건에서 분석했다고 명시한다.
- 사용자 논문과의 거리
  - 직접 라우팅은 아니지만, 차량 네트워크 실험의 지표 설정 방식과 성능 표현 방식이 유사하다.

### 4.8 Design and Implementation of a Connected Car Platform Architecture for New ICT Convergence Services

- 구조
  - connected car platform architecture 제안 → Tizen IVI와 Android 기반 구현 → VSG, vehicle control framework, web framework 제공 기능 설명 → 서비스 프레임워크 확장성 강조 순서다.
- 논리
  - 핵심은 통신 경로 제어가 아니라 서비스 플랫폼 계층을 구성하는 아키텍처 제안이다.
- 문맥과 맥락
  - Connected Car와 ICT Convergence를 상위 맥락으로 두고 차량 제어와 정보 모니터링 서비스로 내려간다.
- 표현
  - 기능 구성 요소와 지원 범위를 열거하는 방식이 강하다.
- 명확성 레벨
  - 플랫폼 구성 요소 설명은 분명하지만, 정량 성능 지표 중심 논문과는 문체가 다르다.
- 신뢰도
  - 실제 구현 플랫폼을 명시한다는 점은 강점이다. 반면 초록 기준으로는 실험 성능 수치가 핵심은 아니다.
- 데이터와 검증
  - 구현 대상 하드웨어와 소프트웨어 플랫폼은 직접 제시되지만, 성능 비교 데이터는 초록 중심으로는 제한적이다.
- 사용자 논문과의 거리
  - 라우팅과 직접 관련되지는 않지만, 차량 통신 시스템을 상위 서비스 구조 속에 위치시키는 문맥 설계 참고용으로는 의미가 있다.

### 4.9 Vehicle control system base on the low power long distance communication technology(NB-IoT)

- 구조
  - NB-IoT 기반 차량 관제 단말 개발 → 주차 차량과 운행 차량에서 수집되는 정보 설명 → 서버 분석을 통한 2차 정보 생성 → 활용 가능성 제시 순서다.
- 논리
  - 장치 개발과 서비스 활용 설명이 결합된 응용 시스템 논문 구조다.
- 문맥과 맥락
  - 차량 도난 방지, 충격 정보 수집, 교통 혼잡과 도로 손상 탐지 같은 응용 사례가 먼저 부각된다.
- 표현
  - 기능 설명 중심이며, 라우팅 계층 논문보다 응용 효과 설명 비중이 높다.
- 명확성 레벨
  - 수집 정보와 활용 방향은 보이지만, 분석 알고리즘과 평가 방식은 초록에서 세밀하지 않다.
- 신뢰도
  - 실제 단말 개발을 명시하므로 구현 사실은 비교적 강하다. 반면 성능 검증 깊이는 초록만으로 한정적이다.
- 데이터와 검증
  - 위치, 상태, 충격 등 수집 데이터 종류는 보이지만 정량 실험 설계는 제한적이다.
- 사용자 논문과의 거리
  - 직접적인 VANET 라우팅 논문은 아니며, 차량 데이터 활용 응용 사례 참고용이다.

### 4.10 Traffic Management in Mobile Ad-hoc Network

- 구조
  - AODV 기반 traffic management support routing protocol 제안 → shortest route와 usable communication resources 고려 → simulation 기반 average reception rate 분석 순서다.
- 논리
  - 노드별 통신 자원 고려가 평균 수신율 향상으로 이어진다는 구조다.
- 문맥과 맥락
  - VANET이 아니라 MANET 일반 맥락에 가깝다. 그러나 AODV 기반 routing decision이라는 점에서 기초 논리 구조가 유사하다.
- 표현
  - 고전 MANET 논문답게 routing protocol과 reception rate를 비교적 직접적으로 연결한다.
- 명확성 레벨
  - 중간 수준이다. 통신 자원의 종류와 shortest route 계산 방식은 초록만으로 구체적이지 않다.
- 신뢰도
  - simulation evaluation을 명시하므로 최소한의 검증 근거는 분명하다.
- 데이터와 검증
  - average data reception rate와 node mobility를 성능 비교 축으로 사용한다.
- 사용자 논문과의 거리
  - 직접적인 차량 통신 표준 기반 논문은 아니지만, AODV 계열 의사결정 기준 서술의 초기 형태를 보여준다.

## 5. 공통 구조 패턴 분석

초록 기준으로 확인되는 JKSCI 유사 논문들의 구조는 대체로 아래 순서를 따른다.

1. 상위 환경 또는 응용 무대 제시
2. 기존 방식 또는 기존 환경의 한계 제시
3. 제안 대상 또는 개선 포인트 제시
4. 검증 방법 제시
5. 성능 또는 장점 요약

이 패턴은 10편 중 특히 아래 논문에서 선명하다.

- 2025 Extended AODV Protocol
- 2024 Digital Twin-based VANET Simulation
- 2018 CRL Processing Time Minimization
- 2016 eMBMS-based CRL Distribution
- 2012 VANET Cache Management

즉 JKSCI 계열에서 사용자 주제와 가까운 논문들은, 초록 단계부터 방법 세부 절차를 길게 풀기보다 먼저 문제 환경과 기존 방식 한계를 세운 뒤 제안 요소를 한 번에 제시하는 구조를 선호한다.

다만 이 구조에는 한계도 있다.

- 상위 맥락은 열지만 세부 전달 단계 설명은 짧다.
- 입력 변수의 의미를 2레벨 이상으로 풀어 설명하는 방식은 드물다.
- 왜 특정 판단 지점이 핵심 제어 지점인지까지는 초록에서 충분히 확장하지 않는 경우가 많다.

이 점은 사용자 논문이 차별화할 수 있는 지점이다. 즉 JKSCI 스타일을 따르되, 사용자 논문은 현재 RREP를 처리 중인 차량, 해당 시점의 Channel Busy Percentage, 이웃 차량 수, hop count, threshold 적용 위치를 더 명확하게 풀어 쓰는 편이 오히려 강점이 될 수 있다.

## 12. 사용자 논문 작성에 직접 적용할 수 있는 결론

### 12.1 유지해야 할 JKSCI형 장점

- 상위 환경 → 문제 → 제안 → 검증 순서를 유지한다.
- 초록과 서론 초반에서 제안 기법을 너무 늦게 꺼내지 않는다.
- 시뮬레이션 기반 검증이라는 점을 초록 단계부터 분명히 둔다.

### 12.2 JKSCI 평균 수준보다 더 강화해야 할 지점

- 현재 RREP를 처리 중인 차량이라는 주체를 반복적으로 명시한다.
- Channel Busy Percentage만으로는 왜 부족한지, 이웃 차량 수와 hop count가 왜 필요한지 각각 따로 푼다.
- hop count 값과 hop count가 1 이하인지 여부가 각각 어떤 역할을 하는지 구분한다.
- baseline을 기존 문헌의 고정 threshold처럼 쓰지 말고, 사용자가 제안한 기준이면 이 연구의 reference method 또는 비교 기준이라고 정확히 쓴다.

### 12.3 특히 참고할 만한 논리 패턴

- 2025 Extended AODV Protocol
  - 기존 방식의 적용 범위 한계 → 표준 프로토콜 확장 제안
- 2024 Digital Twin-based VANET Simulation
  - 단순 평가 환경의 한계 → 현실 환경 기반 평가 필요성
- 2018 CRL Processing Time Minimization
  - 지연 민감 응용 제약 제시 → 계산 위치 재배치로 문제 해결
- 2016 eMBMS-based CRL Distribution
  - 기존 자원 비효율 지적 → 다른 전송 구조로 해결

사용자 논문도 이와 유사하게 다음 구조를 취하는 것이 적절하다.

- IEEE 802.11bd 기반 차량 통신 환경에서는 경로응답(Route Reply, RREP) 전달 판단이 성능에 직접 영향을 준다.
- 기존의 단일 Channel Busy Percentage 기준은 현재 시점의 전송 경쟁 상태와 라우팅 전달 단계를 충분히 반영하지 못한다.
- 따라서 현재 RREP를 처리 중인 차량이 관측한 Channel Busy Percentage, 이웃 차량 수, hop count, hop count가 1 이하인지 여부를 함께 사용해 threshold를 산출해야 한다.
- 이 threshold는 오프라인 로그 분석으로 선택하고, 온라인 단계에서는 딥러닝 기반 회귀모델로 즉시 추정한다.
- 이후 시뮬레이션으로 전달 성공, 지연, 경로 형성 관련 지표를 비교 검증한다.

## 13. 최종 판단

이번 10편 분석으로 확인되는 핵심은 다음과 같다.

- JKSCI에서 사용자 논문과 가장 가까운 직접 선행은 많지 않다.
- 가장 가까운 축은 AODV 확장, VANET 시뮬레이션, 차량 네트워크 자원 제어, 차량 통신 지연 민감 처리 문제다.
- JKSCI 유사 논문들은 구조는 비교적 단정하지만, 변수 정의와 판단 맥락을 2레벨 이상으로 세밀하게 푸는 경우는 드물다.
- 따라서 사용자 논문은 JKSCI형 간결한 구조를 유지하되, 문맥과 맥락, 그리고 변수 정의의 명확성 수준은 그 평균보다 더 높게 가져가는 편이 오히려 장점이 된다.

즉, 사용자 논문은 JKSCI의 전형적인 형식을 그대로 흉내 내기보다, JKSCI의 구조적 안정성을 바탕으로 하면서도 현재 RREP 전달 판단 문제를 더 명확하고 더 근거 중심으로 서술하는 방향이 적절하다.
