AODV Route Discovery Control Scheme Using Local Channel Busy Percentage for Improved Packet Delivery Ratio in VANETs  

[Abstract]

Conventional AODV does not account for channel utilization in route discovery at intermediate nodes. This paper proposes CBP-AODV, a method that controls new RREQ initiation and RREP generation at intermediate vehicle nodes using local Channel Busy Percentage (CBP). The CBP distribution for each control target is divided into four intervals, and interval membership is added to the existing AODV conditions. If the CBP condition prevents RREP generation, forwarding of the received RREQ also terminates. The CBP measurement function defined in IEEE 802.11bd is implemented in an IEEE 802.11p-based model. Twelve configurations are compared across nine scenarios combining vehicle counts and configured maximum speeds. PDR is defined as the percentage of Ping requests whose corresponding replies reach the source. <span style="color: blue;">In the original 279-run evaluation,</span> applying the highest CBP interval from each distribution to both decision points yields the highest PDR averaged across all scenarios, 62.81%, exceeding conventional AODV by 23.05 percentage points. CBP-AODV also reduces the reception failure rate of Ping messages at the physical layer, contributing to the improvement in PDR.

▸Key words: VANET, CBP-AODV, Channel Busy Percentage (CBP), RREQ Control, RREP Control

I. Introduction

차량 애드혹 네트워크(Vehicular Ad Hoc Network, VANET)는 도로 위험 정보의 공유, 교통 흐름 관리, 도로 상태 및 서비스 정보의 제공 등 다양한 지능형 교통 서비스에 활용된다. 이러한 서비스에서는 차량이 필요한 정보를 수신하여 활용할 수 있어야 하므로, 데이터 패킷의 손실과 전달 지연은 통신 성능의 중요한 문제가 된다. 특히 여러 차량이 같은 무선 채널을 이용하여 정보를 교환하는 환경에서는 차량의 통신 수요와 채널 접근 경쟁을 함께 고려해야 한다. 따라서 차량 통신을 활용하는 서비스를 지원하기 위해서는 데이터 패킷을 안정적으로 전달하기 위한 통신 기법이 필요하다.

VANET은 차량 노드 간 무선 통신을 이용하여 정보를 교환하는 네트워크이다. 출발지 차량 노드와 목적지 차량 노드가 직접 통신할 수 없는 경우에는 중간 차량 노드가 데이터 패킷을 전달하여 통신을 지원할 수 있다. 이때 출발지 차량 노드의 데이터 패킷이 목적지 차량 노드에 도달하려면 중간 차량 노드를 거치는 라우팅 경로가 필요하다.

VANET에서는 차량의 이동으로 이웃 차량 노드와 무선 링크의 연결 상태가 달라지므로, 데이터 패킷을 전달하던 라우팅 경로를 계속 사용할 수 없는 상황이 발생한다. 따라서 라우팅 프로토콜은 목적지 차량 노드까지 이용 가능한 라우팅 경로를 구성하고, 기존 라우팅 경로를 사용할 수 없을 때 새로운 라우팅 경로를 확보할 수 있어야 한다. 차량 이동에 따른 라우팅 경로의 변화는 VANET의 데이터 전달 성능에 영향을 주는 주요 요인이다.

AODV(Ad hoc On-Demand Distance Vector)는 데이터 패킷을 전달할 라우팅 경로가 필요할 때 라우팅 경로를 탐색하는 라우팅 프로토콜이다 [1]. 출발지 차량 노드는 목적지 차량 노드까지 이용 가능한 라우팅 경로가 없으면 경로 요청 메시지(Route Request, RREQ)를 전파한다. 목적지 차량 노드 또는 기존 응답 조건을 충족한 중간 차량 노드는 경로 응답 메시지(Route Reply, RREP)를 생성한다. RREQ 출발지 차량 노드는 수신한 RREP의 정보를 이용하여 목적지 차량 노드까지의 라우팅 경로를 구성한다.

중간 차량 노드는 AODV의 라우팅 경로 탐색 과정에서 새로운 RREQ를 시작하거나 보유한 라우팅 경로를 이용하여 RREP를 생성할 수 있다. 본 실험에서 사용한 AODV 구현에서 중간 차량 노드는 전달할 데이터 패킷의 목적지 차량 노드까지 이용 가능한 라우팅 경로가 없으면 새로운 RREQ의 시작 여부를 판단한다. 또한 RREQ를 수신한 중간 차량 노드는 목적지 차량 노드까지의 유효한 라우팅 경로를 보유하고 기존 RREP 생성 조건을 충족하면, 해당 라우팅 경로의 정보를 포함한 RREP를 생성할 수 있다. 새로운 RREQ 시작은 라우팅 경로의 탐색을 시작하는 동작이며, RREP 생성은 이미 보유한 라우팅 경로의 정보를 RREQ 출발지 차량 노드에 제공하는 동작이다.

그러나 기존 AODV는 중간 차량 노드가 새로운 RREQ의 시작 여부와 RREP의 생성 여부를 결정할 때 해당 중간 차량 노드가 관측한 채널 사용 상태를 직접 반영하지 않는다. 중간 차량 노드가 새로운 RREQ를 시작하면 주변 차량 노드에서 RREQ 전달이 이어지면서 다른 패킷의 채널 접근 경쟁이 증가할 수 있다. 또한 중간 차량 노드가 생성한 RREP의 라우팅 경로 정보를 RREQ 출발지 차량 노드가 이용하면, 이후 데이터 패킷은 해당 중간 차량 노드를 거쳐 전달된다. 따라서 중간 차량 노드 주변의 채널 사용 상태는 추가적인 RREQ 전송뿐 아니라, RREP가 제공한 라우팅 경로를 통한 데이터 패킷 전달에도 관련된다.

이러한 문제를 해결하기 위해 채널 사용률이 높은 중간 차량 노드의 RREQ 시작과 RREP 생성을 일괄적으로 제한하는 것은 적절하지 않을 수 있다. 해당 중간 차량 노드의 라우팅 제어 패킷 전송은 줄일 수 있지만, 목적지 차량 노드까지의 라우팅 경로를 탐색하거나 보유한 라우팅 경로의 정보를 제공할 기회도 제한되기 때문이다. 또한 높은 채널 사용률에는 데이터 패킷의 송수신 활동도 포함될 수 있으므로, 높은 값만으로 해당 중간 차량 노드를 거치는 라우팅 경로가 데이터 전달에 부적합하다고 판단하기 어렵다. 따라서 어떤 채널 사용 상태에서 중간 차량 노드의 RREQ 시작과 RREP 생성을 허용하는 것이 전달 성능에 유리한지 확인할 필요가 있다.

본 연구는 중간 차량 노드가 측정한 채널 사용률(Channel Busy Percentage, CBP)을 이용하여 새로운 RREQ 시작과 RREP 생성을 제어하는 CBP-AODV를 제안한다. CBP는 측정 기간 중 채널이 busy 상태인 시간의 백분율이며, 각 차량 노드가 측정한 값을 local CBP라고 한다 [2]. CBP-AODV는 기존 AODV 조건에 local CBP가 선택한 구간에 포함되어야 한다는 조건을 추가한다. local CBP 조건을 적용받는 중간 차량 노드는 해당 조건을 충족하지 못하면 새로운 RREQ를 시작하지 않으며, RREP 생성에 해당 조건을 적용하는 경우에는 RREP를 생성하지 않고 수신한 RREQ도 전달하지 않는다. RREQ 시작 제어와 RREP 생성 제어의 개별 적용 및 결합 적용에 각각 네 CBP 구간을 적용하여, 제어 대상과 CBP 구간에 따른 패킷 전달 성능을 비교한다. 성능 평가는 IEEE 802.11p 기반 통신 모델에 IEEE 802.11bd의 CBP 측정 기능을 구현한 환경에서 수행하며, PDR과 물리계층에서 Ping 메시지의 수신 실패율을 분석한다.

제II장은 관련 연구를 설명한다. 제III장은 CBP-AODV의 설계 근거와 local CBP 기반 제어 구성을 제시하고, 제IV장은 기존 AODV 처리 과정에 제어 조건을 적용하는 방법을 통합 순서도로 설명한다. 제V장은 실험 설계와 평가 방법을, 제VI장은 실험 결과와 그 해석을 제시한다. 제VII장은 결론과 향후 연구를 정리한다.

II. Related Work

VANET/V2X에서는 차량의 이동과 공유 무선 채널의 사용 상태를 라우팅 및 메시지 전송에 반영하는 연구가 수행되었다. 이 장에서는 선행연구를 AODV 개선, 채널 상태 기반 전송 제어와 부하 평가, IEEE 802.11p/bd 분석으로 구분하고, 각 연구가 사용하는 정보, 변경하는 프로토콜 동작, 평가하는 성능을 비교한다.

1. AODV Routing in VANETs and V2X Networks

Chatterjee 등은 VANET/V2X 라우팅을 학습 기반 방식과 비학습 기반 방식으로 구분하고, AODV를 비학습 기반 반응형 라우팅 프로토콜로 분류하였다 [5]. El-Dalahmeh 등은 동일한 암호화 방식을 적용한 AODV, OLSR 및 DSDV의 패킷 전달 성능과 라우팅 오버헤드를 비교하였다 [6]. 이들 연구는 AODV의 분류와 프로토콜 간 성능 차이를 다루었다.

AODV의 동작을 개선하는 연구에서는 차량 이동 정보와 링크 품질을 활용하였다. Darabkh 등은 차량의 속력과 이동 방향을 라우팅 경로 구성에 반영하고, 속력에 따라 HELLO 메시지의 전송 주기를 조절하였다 [3]. Al-Qassas와 Qasaimeh는 예상 전송 횟수(ETX, Expected Transmission Count)를 사용하는 AODV 변형들을 비교하여 링크 품질을 라우팅 경로 선택에 활용했을 때의 성능을 평가하였다 [4]. 본 연구에서는 중간 차량 노드가 자신이 관측한 채널 사용 상태를 이용하여 새로운 RREQ의 시작 여부와 RREP의 생성 여부를 결정한다.

2. Channel-Aware V2X Transmission Control and Load Assessment

채널 상태 기반 V2X 전송 제어는 차량이 관측한 무선 환경에 따라 전송 매개변수를 조절한다. Balador 등은 분산 혼잡 제어(DCC, Decentralized Congestion Control) 연구를 검토하고, 메시지 전송률, 전송 전력 및 데이터 전송률을 조절하는 방법을 정리하였다 [7]. Cho 등은 수신 신호 강도를 이용하여 패킷 손실이 페이딩과 채널 혼잡 중 어느 상태와 관련되는지 판단하고, 데이터 전송률과 전송 전력을 조절하였다 [8]. St. Amour와 Jaekel은 채널 사용 비율(CBR, Channel Busy Ratio)에 따라 전송 상태를 변경하고, 각 상태에 대응하는 기본 안전 메시지(BSM, Basic Safety Message)의 데이터 전송률을 선택하였다 [9]. 문헌 [10]은 CBR에 따라 IEEE 802.11bd 패킷의 반복 전송 횟수를 조절하였다. 이들 연구는 채널 상태를 메시지 전송률, 데이터 전송률, 송신 전력 또는 반복 전송 횟수의 결정에 사용한다.

관측한 채널 상태를 전송 제어 대신 부하 평가에 사용하는 연구도 있다. Wippelhauser 등은 실제 교통량 자료를 이용한 ITS-G5 시뮬레이션에서 도로변 ITS 스테이션과 차량 ITS 스테이션이 측정한 평균 CBR을 구분하여 채널 부하를 분석하였다 [11]. 이는 관측 주체별 채널 부하를 평가한 연구로, 채널 상태에 따라 라우팅 제어 메시지의 생성 여부를 결정하는 연구와 분석 대상이 다르다.

본 연구에서는 중간 차량 노드가 측정한 local CBP를 AODV의 새로운 RREQ 시작과 중간 차량 노드의 RREP 생성 판단에 사용한다. 이를 통해 채널 상태를 무선 전송 매개변수에 반영하는 선행연구와 달리, 경로 탐색 과정에 반영했을 때의 패킷 전달 성능을 평가한다.

3. IEEE 802.11p/bd Studies and Research Scope

IEEE 802.11bd는 차세대 V2X 통신을 위해 IEEE 802.11p의 물리(PHY, Physical) 계층과 매체 접근 제어(MAC, Medium Access Control) 부계층 기능을 확장하며, 채널이 busy 상태였던 시간의 백분율을 나타내는 CBP 측정 기능을 제공한다 [2]. Ma는 신호 대 간섭및 잡음비(SINR, Signal-to-Interference-plus-Noise Ratio) 분포를 바탕으로 IEEE 802.11p/bd 브로드캐스트 VANET의 계층별 성능과 안전 서비스 지원 성능을 분석하였다 [12]. Xue 등은 IEEE 802.11bd의 일부 개선 기능을 Veins에 구현하여 동적 교통 시나리오에서 두 표준의 데이터 전달 성능을 비교하였다 [13]. Iliopoulos 등은 IEEE 802.11bd의 주요 PHY 계층 및 MAC 부계층 기능과 V2X 서비스 적용 범위를 정리하였다 [14]. 이들 연구는 표준 기능과 무선 통신 성능을 분석한다.

검토한 문헌에서 AODV 개선 연구는 이동 정보와 링크 품질을 라우팅 경로 구성, 선택에 사용하고, 채널 상태 기반 연구는 무선 전송 매개변수를 조절하거나 채널 부하를 평가하였다. 그러나 이 문헌들은 중간 차량 노드의 새로운 RREQ 시작과 보유한 라우팅 경로에 따른 RREP 생성 판단에 해당 노드의 local CBP를 사용하는 방법을 다루지 않았다. 본 연구는 IEEE 802.11p 기반 무선 통신 모델에 IEEE 802.11bd의 CBP 측정 기능을 구현하고, 중간 차량 노드의 새로운 RREQ 시작 여부와 RREP 생성 여부를 결정하는 조건에 local CBP를 추가한다.

III. Design of CBP-AODV

1. Local CBP Measurement

CBP-AODV는 중간 차량 노드가 관측한 국소 채널 사용률(local CBP)을 기존 AODV의 경로 탐색 조건에 반영하는 기법이다. CBP는 측정 기간 중 채널이 busy 상태인 시간의 백분율이며 [2], 각 차량은 자신의 송수신 상태를 이용해 이를 계산한다. 본 구현은 IEEE 802.11p 기반 통신 모델에 CBP 측정 기능을 추가하여 송신 시간과 수신 상태가 BUSY 또는 RECEIVING인 시간을 집계한다.

채널 상태는 시뮬레이션 시작 후 30 s부터 100 ms 주기로 집계한다. AODV는 제어 판단 시점에 진행 중인 주기의 누적 busy 시간을 해당 주기의 경과 시간으로 나눈 값을 사용한다. 경과 시간이 0인 경우에는 직전 완료 주기의 값을 사용한다. 제어 판단에는 반올림하지 않은 값을 적용한다.

2. CBP Interval Configuration

3. Control Configurations

CBP-AODV의 제어 대상은 중간 차량 노드의 새로운 RREQ 시작과 RREP 생성이다. 새로운 RREQ 시작은 전달할 데이터의 목적지까지 사용할 경로가 없을 때 경로 탐색을 시작하는 동작이며, 수신한 RREQ를 다른 노드로 전달하는 동작과 구별한다. RREP 생성 제어는 수신 RREQ에 대해 보유 경로 정보를 제공할 수 있는 중간 차량 노드에 적용한다.

표 2의 세 제어 옵션에 각각 네 CBP 구간을 적용하여 12개 설정을 구성하고, 이를 CBP-AODV(c, Qi)로 나타낸다. 여기서 c는 RREQ, RREP 또는 RREQ+RREP이다. 결합 제어는 두 제어 지점에 같은 번호의 구간을 적용하되, 수치 경계는 각각 표 1을 따른다. 각 실행에서 선택한 구간은 고정하며, 비활성 제어 지점에서는 CBP 조건을 추가하지 않는다. 각 제어의 처리 절차와 예외 조건은 제IV장에서 설명한다.

1. RREQ Initiation Control

그림 1(a)에서 활성 상태이며 다음 홉 주소가 지정된 목적지 경로가 있으면 목적지·다음 홉 경로의 수명을 갱신하고 기존 전달을 계속한다. 경로가 없고 현재 노드에서 생성한 데이터이면 CBP와 관계없이 경로 탐색 대기열에 저장한다. 같은 목적지의 탐색이 진행 중이면 완료를 기다리고, 그렇지 않으면 RREQ를 생성하여 최초 브로드캐스트한다.

중계하는 데이터에 사용할 경로가 없고 RREQ 제어가 활성인 경우에는 현재 CBP를 조회한다. 허용 구간에 포함되면 대기열에 저장하고 기존 탐색을 기다리거나 새 탐색을 시작한다. CBP 조건은 큐 저장과 탐색 진행 여부 확인보다 먼저 적용하므로, 진행 중인 탐색을 기다릴 데이터의 큐 수용에도 영향을 준다.

CBP가 허용 구간에 포함되지 않으면 데이터를 대기열에 저장하거나 새로운 RREQ를 시작하지 않고 IPv4의 일반 처리로 반환한다. 이 분기 자체는 즉시 폐기를 뜻하지 않는다. RREQ 제어가 비활성이면 CBP 검사 없이 기존 대기열 저장 및 탐색 절차를 수행한다.

2. RREP Generation Control

그림 1(b)의 기존 수신 처리는 블랙리스트 확인, 이전 홉 경로 생성·갱신, 중복 RREQ 확인, 홉 수 증가, 역방향 경로 생성·갱신 순서로 진행한다. 블랙리스트 또는 중복에 해당하면 해당 단계에서 종료한다. 현재 노드가 수신 RREQ의 목적지이면 CBP 조건 없이 RREP를 생성하여 역방향 경로로 전송하고 종료한다.

목적지가 아닌 노드는 활성 목적지 경로와 유효한 목적지 순서 번호를 보유하고, 그 번호가 RREQ의 요청 값 이상인지 확인한다. 이 조건을 충족하더라도 목적지 경로의 다음 홉이 RREQ의 이전 홉과 같으면 루프 방지를 위해 먼저 종료한다. 이 종료 분기에 해당하지 않고 목적지 전용 플래그가 설정되지 않은 노드가 중간 응답 후보가 된다.

중간 응답 후보에 RREP 제어가 활성화되어 있으면 현재 CBP를 조회한다. 목적지까지 1홉인 경로의 다음 홉이 목적지인 직접 연결 예외에 해당하거나 CBP가 RREP 허용 구간에 포함되면 기존 중간 RREP 생성 절차로 진행한다. 직접 연결 예외는 기존 응답 자격을 충족한 분기 안에서만 적용한다. RREP 생성 절차에는 목적지·역방향 경로 항목의 존재와 관리 주체 재확인이 포함되며, 정상적으로 생성한 RREP는 역방향 경로로 전송한다.

직접 연결 예외가 아니고 CBP도 허용 구간에 포함되지 않으면 RREP를 생성하지 않고 수신 RREQ의 처리를 종료한다. 이때 RREQ를 재전달하지 않는다. RREP를 생성한 분기도 응답 후 종료하며 RREQ 전달 분기로 이어지지 않는다. 반면 중간 응답의 경로 조건을 충족하지 못하거나 목적지 전용 플래그가 설정되어 전달 검토 분기에 도달한 RREQ는 기존 절차를 따른다. 남은 TTL이 0보다 크고 AODV 재시작 대기 시간이 끝났을 때 목적지 순서 번호를 갱신하여 전달하며, 그렇지 않으면 종료한다. 루프 방지나 CBP 불허로 종료한 RREQ를 이 전달 분기로 다시 보내지 않는다.

따라서 데이터 처리의 CBP 불허는 큐 수용 없이 IPv4로 반환하며, 수신 RREQ의 CBP 불허는 중간 응답과 해당 RREQ의 전달을 종료한다.

V. Experimental Methodology

1. Simulation Environment

차량 이동과 무선 통신을 연동한 시뮬레이션으로 CBP-AODV를 평가하였다. 네트워크에는 OMNeT++ 6.0.3과 INET 4.5를, 차량 이동에는 SUMO 1.0.1을 사용하였다. Veins를 통해 시뮬레이션 시간을 연동하고 차량의 위치를 통신 노드에 반영하였다. 도로변 통신 장치(Roadside Unit, RSU) 한 대를 도로망 중앙에 고정 배치하고, 차량 노드는 IPv4와 AODV를 사용하도록 구성하였다.

도로 네트워크는 OpenStreetMap에서 취득한 서울특별시 강북구 미아동 일대의 도로 자료를 바탕으로 구성하였다. SUMO 1.0.1의 netedit로 도로망을 편집하고 duarouter로 차량별 이동 경로를 생성하였다. 그림 2는 대상 지역과 실험에 사용한 SUMO 도로 네트워크를 나타낸다.

무선 통신에는 IEEE 802.11p 기반 모델을 사용하고, IEEE 802.11bd의 CBP 측정 기능을 추가하였다 [2]. 표 3에 시뮬레이션과 트래픽 설정을 정리하였다. 차량 대수 70·100·120대와 최대 속력 10·20·30 km/h를 조합한 9개 시나리오를 구성하였다. 최대 속력은 이동 모델에 설정한 속력 상한이다. 각 시뮬레이션 시나리오는 목적지 차량 노드를 변경하여 31회씩 수행되었다.

3. Performance Metrics and Aggregation

패킷 전달률(Packet Delivery Ratio, PDR)은 RSU가 전송한 Ping 요청 중 대응 응답이 RSU에 도달한 비율로 정의한다. 한 실행의 요청 전송 수를 Nreq, 대응 응답 수를 Nrep라 하면 다음과 같다.

VII. Conclusions

본 논문은 차량용 애드혹 네트워크의 패킷 전달 성능을 향상시키기 위해 국소 채널 사용률을 AODV의 경로 탐색 조건에 반영하는 CBP-AODV를 제안하였다. 중간 차량 노드의 새로운 RREQ 시작과 RREP 생성을 개별 또는 함께 제어하고, 각 제어 지점의 CBP 허용 구간에 따른 결과를 비교하였다. 차량 대수와 설정 최대 속력을 조합한 9개 시나리오에서 12개 설정을 평가하여, 제어 방식과 구간 선택이 전달 성능에 미치는 차이를 확인하였다.

평가한 설정 중 두 제어에 가장 높은 CBP 구간을 함께 적용한 설정의 전체 평균 PDR이 62.81%로 가장 높았으며, 기준 AODV의 39.76%보다 23.05%p 향상되었다. 이때 물리계층에서 Ping 메시지의 수신 실패율은 평균 30.87%에서 11.64%로 감소하여 PDR 향상에 기여하였다. 목적지별 PDR 개선량의 중앙값도 20.67%p로 양수여서 평균과 분포의 중심에서 개선을 확인하였다. 한편 환경별 최적 구간은 달랐으며, 결합 설정에서 PDR이 감소한 관측은 15.1%였다.

<span style="color: green;">목적지 차량 10대와 시드 5개를 조합한 450회 평가에서 결합 Q4의 평균 PDR은 기준 AODV보다 21.68%p 높았다. 결합 Q4의 평균 PDR은 시드 5개 각각과 목적지 차량 10대 각각에서도 기준 AODV보다 높았다. 결합 Q4의 PDR은 허용확률까지 판단마다 바꾸는 첫 번째 무작위 방식보다 높았으며, Q4의 허용 비율을 고정 확률로 적용한 두 번째 무작위 방식과는 비슷하였다. 두 번째 무작위 방식과 비교했을 때 결합 Q4는 더 적은 경로 탐색 메시지를 송신하고 낮은 물리계층 Ping 수신 실패율을 보였다. 따라서 추가 평가의 결과는 동일한 도로망에서 결합 Q4의 시드별 PDR 변화를 확인하고, PDR이 비슷한 결합 Q4와 두 번째 무작위 방식의 제어 메시지 송신량 차이를 함께 보여준다.</span> <span style="color: green;" data-review-tags="true">(리뷰어1-1) (리뷰어1-2) (리뷰어1-3) (리뷰어3-1·리뷰어3-2 중복 대응: 동일 도로망 내 추가 검증)</span>

<span style="color: gray;">의도: 결론의 개선 주장을 시드·목적지별 결과와 무작위 대조군 비교로 구체화한다.</span>

<span style="color: purple;">표 8에서 결합 Q4는 기준 AODV보다 경로 탐색 메시지를 85.06% 적게 송신하였고, 응답이 도착한 Ping의 조건부 평균 RTT도 낮았다. 추가 평가에서는 450개 대응 실행 중 41개에서 PDR이 감소하였다. 따라서 본 연구의 성능 결과는 전체 평균과 개별 목적지·시드 조건을 함께 고려하여 해석한다.</span> <span style="color: purple;" data-review-tags="true">(리뷰어3-3) (리뷰어2-6·리뷰어2-9 중복 대응)</span>

<span style="color: gray;">의도: 결론에서 추가 지표의 개선과 개별 실행의 성능 차이를 함께 정리한다.</span>

<span style="color: blue;">본 연구는 시드 1의 기준 AODV 자료 279회로 정한 CBP 구간 경계를 유지한 채, 별도의 시드 2~5에서 결합 Q4의 전달 성능을 평가하였다. 시드별 기준 AODV 자료에서 다시 계산한 CBP 경계는 원래 경계와 최대 1%p 차이였으며, 표 1의 경계를 고정해 적용한 360회 평가에서 결합 Q4의 평균 PDR은 기준 AODV보다 약 21.0%p 높았다.</span> <span style="color: blue;" data-review-tags="true">(리뷰어2-5)</span>

<span style="color: gray;">의도: 동일 도로망에서 고정 경계를 다른 시드에 적용했을 때의 PDR 결과를 정리한다.</span>
